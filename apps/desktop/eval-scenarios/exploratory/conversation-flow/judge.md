# CHAT-01 候选判据：独立 Judge 与人工复核

暂无获批 PRD/Check。运行前冻结本文件版本，逐项给 `pass / fail / inconclusive / not_evaluated`、理由和原始证据指针。本文件不交给 Driver 或被测产品；同上下文切换角色不算独立评审。

1. **CHAT-TURN｜A：真实会话完成（必需）**。首轮用户消息经真实 UI 发送，得到同一产品 `session_id` 下可追溯 turn 的完整终态答复；动作 seq、消息、终态和截图能对应目标构建。仅 `ack.ok`、`running=false`、输入框复位、进度或历史旧答复不能通过。缺身份或正文记 `inconclusive`；明确发送失败或产品错误记 `fail`。
2. **CHAT-QUALITY｜B：切题且可用（必需）**。答复围绕指定的大学生睡眠干预与学习表现研究，提出两条可据题名/摘要操作的纳入标准、一条合理排除标准，并说明摘要关键信息不足时应保留待核全文或标记待定，而不是虚构结论。允许不同表述；空泛闲聊、改题或给出无依据的确定研究结论不通过。计数、关键词只作线索，必须阅读完整答复判定。
3. **CHAT-BOUNDARY｜边界与证据（必需）**。没有擅自搜索、下载、修改文献或读取无关项目；若证据不足以排除明显副作用，说明缺口并给 `inconclusive`。回复截断、来源错位或目标版本无法确认，不给整体通过。
4. **CHAT-FOLLOWUP｜同会话追问（可选扩展）**。只有 Driver 实际执行时判定：第二轮保持同一 `session_id`，先前 turn 完成后才发送；答复正确把对象从大学生调整为中学生，保留睡眠干预与学习表现主题，并解释相应纳入/排除标准的调整。不执行记 `not_evaluated`，不纳入首轮通过分母。

首轮必需项出现 `fail`，首轮整体为 `fail`；没有失败但缺必需证据为 `inconclusive`；全部必需项 `pass` 才为 `pass`。执行受阻而未发送时为 `not_evaluated`，另报 `blocked` 原因。不要用可选追问的结果覆盖首轮失败。
