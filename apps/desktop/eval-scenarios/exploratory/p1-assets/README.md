# P1配套资产与准备交接

本目录只保存合成输入及人工准备说明，不是新执行器。四套场景复用这里的资料；项目、模型和账户复用原场景资产。业务点唯一真源仍是[目录](../../../docs/scenarios/catalog.json)；本次不新增/删除/调级点位，不改变默认P0，不修改产品逻辑或规则。

## 本次资产准备的完成定义

- 41点=10个P0点+31个P1点，按既有12个方向筛选；不是把103行用例全部纳入，也不将同点变体无条件连带执行。
- 原29个缺口点现在有独立执行步骤、必需Check、候选判据和资料/参数约定。manual_ready只表示人工输入资产齐备，不表示有自动runner或真实前提已满足。
- 专用模型密钥、账户登录、Zotero进程、两模型调用授权、平台实例、目标构建与运行预算必须在未来执行前核实。**这些外部前提本次不创建、不授权、不存值**；缺前提记阻塞，不偷偷借现有凭据。
- 来源/历史观察仍保留pending、candidate_unapproved和证据缺口，不因补资产晋升正式覆盖或宣称结果通过。Windows仅独立清单/资产检查，没有启动或实机验收。
- 三件套中的status不是业务执行；不能仅运行cmd就声称41点已测完。冻结资产后，执行只读冻结版本；禁止边测边补资产、临时换资料/判据/范围或重试到绿。

## 未来运行前的非秘密参数

| 参数 | 必要核对与不满足时处理 |
| --- | --- |
| 目标实例/构建/平台/语言 | 安装位置、包摘要、签名、精确PID及Home/profile/workspace；macOS和Windows独立运行，不在两台机器间复制登录态 |
| 任务对象 | 唯一run标签、项目A/B及根、session/turn、文献/附件与源revision；只操作本轮明确创建的合成对象 |
| 模型授权 | 逐点计划所需用户触发动作、必要确认/取消、内部调用费用、独立Judge方向数及连续时限；不沿用P0的7次或30分钟预算覆盖完整P1 |
| 两模型 | CHAT-MODEL-SWITCH须确认两个不同且获准可调用模型；缺其一阻塞该点，不能用选择标签猜执行身份 |
| 模型配置 | MODEL-CONFIG使用专用可信端点、允许模型列表和临时测试密钥，由操作者在正常UI输入；参数记录只存获准标识与遮挡状态，密钥不进Git/截图/报告 |
| 账户 | ACCOUNT-LOGIN须专用隔离未登录态和获准测试身份；操作者正常登录；恢复默认仅菜单关闭重开，进程重开必须另获准并冻结范围 |
| Zotero | 专用真实Zotero profile与合成库；从UI导入两份bib分别到EVAL-SELECT/EVAL-CONTROL，保存源库身份、分类及版本。仅授权后启用其正常Local API；不安装/修改系统配置、不读取个人库、不搭假API代替真实产品 |
| 网络与导入 | 公开论文检索、上传/复制资料、Zotero本机连接逐项核授权；DISC候选可同轮复用，不能用历史候选冒充本轮发现 |
| 任务写入与归档 | 只允许任务owned路径/项目/资料/会话；需要保存/替换/恢复/归档的分支先核授权与备份，不能删未知数据或复制文件制造通过 |
| 设置恢复 | autosave在核隔离后才允许切换；记录原值，结束用正常UI恢复。无法确认设置作用域则阻塞，不擅改产品默认规则 |

所有参数、资料摘要、动作预算、依赖顺序及范围应在正式执行前确认与冻结；运行时发现缺失只阻塞相关点，其他独立就绪点继续。准备资料副本不等于提前执行必测业务动作；项目创建、导入、真实对话等仍按所选计划在业务窗口计时。

## 合成资料与前提构造

- `fixtures/树/`：根与带中文空格子目录，覆盖层级/文件内容/源未改检查。
- `fixtures/conflict/{old,new}/计划.md`：内容A/B不同，分别复制到本轮staging；重命名、替换、历史恢复使用不同任务子目录，不让前一项污染后一项。
- `fixtures/reference/{alpha,beta}/事实.md`：同名不同内容，用于项目资料引用、本地附件、任务引用及产物的来源对照。Driver可见输入事实，不包含独立Judge结论。
- `fixtures/document.pdf`：两页英文合成研究，各页数字与限制不同，供文献导入、逐页翻译和全文解读；`fixtures/supplement.pdf`是独立单页附件。生成/完整性检查由[fixtures.mjs](fixtures.mjs)固定文本可复现，消费测试核页数/内容和确定性字节；不是产品PDF能力验收。
- `fixtures/selected.bib`与`control.bib`：真实Zotero导入的合成题录；无伪造DOI，不能拿它们替代公开论文检索。题录引用任务只给selected摘要、不附全文；带PDF的文献任务使用另一个独立条目，避免偷换证据前提。

前提依赖要单列真实动作及费用，不能让“只测管理”掩盖模型准备调用：
- CHAT-NEW → 同会话修订 → 获准第三个短回合 → CHAT-HISTORY；准备时明确三回合上限，历史点核三处不同消息。可复用当前attempt对应已完成结果，但报告注明复用与新操作，不重复计模型费用。
- CHAT-ARCHIVE → CHAT-RESTORE只操作completed任务；PROJ-ARCHIVE → PROJ-RESTORE用独立空闲任务项目，两组互不污染。前提受阻可使用另一个在冻结输入中已确认的本轮合成对象；不能运行中改计划造前提。
- LIT-IMPORT-PDF → 项目关联/附件；DISC本轮候选 → LIT-SEARCH-SAVE。Zotero导入不能用本地PDF导入代替，检索保存不能用手工题录新建代替。
- CHAT-ARTIFACT → CHAT-ARTIFACT-IMPORT；没有真实发布结果不能用宿主代写文件补上。
- RES-CONFLICT-REPLACE → 历史恢复；autosave用独立MD。历史恢复所需两次保存属于真实动作，不直接修改版本数据库。
- CHAT-STOP需要真实正在生成的回合；自然结束未停到是inconclusive，不无限重发。
- MODEL/ACCOUNT各保留原4项严格判据；只读目录、已有账号、正常启动或一次UI显示不替代真实配置/登录与状态保持。

## 采证与判断交接

逐点保留操作前对象水位、原请求/回执、task或session/turn及实际模型、完整结果/终态与同身份只读落盘/列表对照；用DamoATrace CLI读精确源，不解析原生rollout或隐藏推理。归档/还原、替换/恢复及设置双分支需要前后证据，不由最终截图推断历史。外部副作用只有声明范围覆盖充分才可判通过。

每条Check的报告默认含A/B/合并四态及可点击原图，图逐张检查；缺图、未执行、缺授权或缺范围覆盖必须明示。未观察到错误不是自动pass；确证fail不能改判据/降要求/重试洗绿，补测新attempt，历史不覆盖。发现产品问题只记录证据交开发。
