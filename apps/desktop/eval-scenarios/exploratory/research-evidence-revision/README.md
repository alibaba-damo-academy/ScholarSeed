状态：**探索场景，已有一次试跑但未通过候选判据**。2026-10-19 对构建 `202610191654` 完成两轮产品对话；独立评审发现第二轮完整回答超出 150 字限制，副作用证据仍不完整。该次资料经产品公开导入 API 准备，未覆盖下文要求的原生文件选择器；运行报告和原始证据保存在本机忽略目录，不作为当前分支的验收结果。本场景当前没有对应的已批准 PRD Requirement/Check，不能计入发布覆盖，也不能把 `baseline.json` 当作实际运行结果。

目标：让真实产品读取项目中的两份研究资料，给出有资料依据的比较回答，然后在**同一会话**按新的表达要求修订。资料是为评测编写的合成材料，不含用户数据或凭据。

## 文件职责

- `scenario.json`、`cmd.jsonl`、`baseline.json`：沿用现有场景三件套；`cmd.jsonl` 只有预检指令。实际操作须在本次运行副本里按观察追加。
- `fixtures/`：唯一资料真源。暂存为 `sources/`，经产品导入后位于隔离项目的 `resources/sources/`。
- `driver.md`：只包含用户可见任务与操作边界。正式驱动应由**未读取 `judge.md` 的独立上下文**承担。
- `judge.md`：探索性人读判据与参考事实，仅交独立评审，不导入产品项目、不交给 Driver。

## 运行前提与计时

记录候选 Git commit／构建包摘要、平台、实际模型、隔离且已初始化的 Home、产品项目、资料哈希，以及产品、Driver、Judge 的预算和停止条件。候选版本可运行且环境就绪后，到结果报告为止，以 30 分钟为首轮**待实测目标**；准备与构建耗时另记。时间到界停止新增操作，保留失败及缺证并报告实际耗时，不为凑通过延长或重试。未满足前提时报告 `blocked`，不得借用用户正在运行的安装版冒充候选版本。

## 项目与资料准备

复制本目录到本次忽略运行目录，保持入库原件只读。由 Observer 把两份 fixture 按 `scenario.json` 物化到本次独占的 `sources/` 目录，记录原始与暂存文件摘要；不要把 `judge.md` 放入该目录。`--drive` 只读取 `cmd.jsonl`，不会自动创建项目或应用 `project.files`。启动候选产品前分别设置本次独占的 Home、默认项目工作区、Electron profile 与调试端口，并在产品内读回实际生效的项目根，不只相信环境变量。

经真实产品 UI 完成首启，新建唯一项目并读回项目 ID、根路径与当前绑定。新建的 managed 项目以 `resources/` 为资料根；在资料库使用“导入本地资料 → 复制到项目”的原生文件选择器选择暂存的 `sources/` 目录，实际项目路径应为 `resources/sources/`。Composer 的 `attach` 只会添加会话附件，不满足本场景的项目资料前提。导入提示仅表示入队：待任务及来源均成功，再刷新资料树，确认 `resources/sources/study-a.md`、`resources/sources/study-b.md` 的实际路径，分别在产品中打开核对正文，并核对已导入文件与暂存文件的摘要。必要时用产品公开项目、导入任务和资料树读接口辅助确认身份；若目录被改名、导入未完成、打开内容不符，先修正准备阶段或报告 `blocked`，不发送业务问题。

启动 `--drive` 后按 [driver.md](driver.md) 观察并追加命令；其 `status` 只提供会话/运行状态，不能证明项目或资料身份。固定等待、`ack.ok`、`running=false` 或文件名出现在回答里都不足以证明业务完成。

冻结并复核两轮真实消息与答复、同一 session 的 turn/动作序号、来源读取和上下文 Trace 指针、最终截图及任何产物。按 [judge.md](judge.md) 逐项给 `pass / fail / inconclusive / not_evaluated`，区分执行状态与语义结论，保留首轮失败和缺证。报告必须注明这次只覆盖所记录的平台、模型、账号态和候选版本。
