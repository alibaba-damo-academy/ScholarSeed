# SKILL-01 候选判据：独立 Judge 与人工复核

暂无获批正式 PRD/Check，本场景只作探索。运行前冻结本文件版本，逐项给 `pass / fail / inconclusive / not_evaluated`、理由和原始证据指针。本文件不交给 Driver 或被测产品；同上下文切换角色不算独立评审。A 类事实由 Observer/测试 Owner 核验，B 类由隔离的独立 Judge 或独立人工评审，不以其中一类抵消另一类失败。

1. **SKILL-SELECT｜A：真实选择与执行身份（必需）**。目标构建的真实技能中心显示稳定 ID 为 `design-research-validation` 的内置条目并打开其说明；真实 Composer 技能选择器形成该 ID 的 selected reference，实际 name/id、path、version 可与本轮请求及执行端接受/加载的技能身份关联。原始请求、产品 `session_id`/turn、动作 seq 与终态结果属于同一执行范围。仅在消息中提到名字、中心 enabled 勾选、UI 引用标签、宿主事后自述或其他会话的结果都不足以证明调用。真实请求明确未携带目标技能、调用错误技能或身份错位为 `fail`；本轮已执行但必要传递/执行证据缺失为 `inconclusive`。因登录、active、模型或授权等前提受阻而未发送时为 `not_evaluated`，另报阻塞，不直接归为产品缺陷。
2. **SKILL-RESULT｜B：方案可行且结论有界（必需）**。独立阅读同回合完整答复：围绕12名志愿者、两周内部试点和无对照的单组前后设计，提出两项可在该限制内实施、互有用途的验证步骤，并分别说明应收集的证据；将方案和未来数据与已发生事实区分。答复明确仅凭此设计不能证明功能导致变化，也不能证明对更广人群普遍有效，不臆造实测数据、效果或已完成实验。不要求固定措辞、特定统计检验或任务未给出的数值门槛；可以给明确标注的假设或后续更强设计建议，但不能把新增对照组、扩大样本或延长周期作为本次两项步骤的既成前提。关键词与条数只作线索，必须按完整语义判断；仅拒绝作答而不给可用方案、改题或无依据宣称有效为 `fail`。正文截断或来源身份无法核实时为 `inconclusive`。
3. **SKILL-BOUNDARY｜A：同回合终态与禁止副作用（必需）**。原始用户请求、同一 `session_id`/turn 的实际终态、完整工具/任务记录和可见产物共同证明只在对话交付，没有执行被禁止的检索、下载、创建/修改用户或项目文件、实验或实验代码执行。读取目标技能说明及必要只读技能加载与业务检索区分；产品正常会话/日志持久化与模型受托写文件区分。不能用正确答复、空工具列表截图、静态关键字、无可见新文件、`running=false` 或发送按钮恢复替代同回合原始证据。明确发生禁止操作为 `fail`，随后取消或答复合规不抹掉违规；已执行但工具/任务范围、终态或产物证据不足以核对边界为 `inconclusive`。从未发送则为 `not_evaluated`，不以 UI 已选中冒充执行。

三项必需 Check 任一 `fail`，本场景整体为 `fail`；没有失败但缺必需证据或独立语义评审为 `inconclusive`；全部必需项 `pass` 才为 `pass`。前提受阻而未发送时报告 `not_evaluated` 与具体阻塞；预算停止不改写已发生的失败。只保留本轮事实与缺口，不把本候选判据或单次结果晋升为正式覆盖、基线批准或 Windows 验收。


## 第三档补充Check

4. **SKILL-BROWSE｜A：浏览分组与内置技能说明（必需）**。目录可浏览，分组和详情关联真实技能ID，切换后名称/说明不残留另一条；不切启用、不安装、不调用技能或检索，不把当前文案当批准精确需求。 必须保存同身份的前后状态、完整结果及结果原图；有确证错误为fail，执行但缺必要证据为inconclusive，缺前提/权限而未执行为not_evaluated，不把操作回执或单图当功能结果。

补充Check仅在选中P2点时执行；既有P0/P1判据不变。禁止改判据、降低要求、反复重试洗绿；新补测另开attempt，历史不覆盖。产品问题只留缺陷和证据，不改产品逻辑或规则。
