## Current Source Analysis and Boundaries

Source baseline `acce09fa42ddf234d84b02dde34b2ab4be570215`; `Navigation.tsx`, `Tasks.tsx`, and `api.ts` checked here had no uncommitted differences from this commit. This source has no trusted binding to the target installed package; source presence does not prove UI reachability or requirements correctness.

- **Entry point and fixed content:** Project navigation in [Navigation.tsx](../../../src/renderer/src/features/project/Navigation.tsx) displays task titles, pinned group, and ordinary-task area. `pinnedTasks` and `unpinnedTasks` come from grouping results; the pinned area appears only when non-empty. Rows are assembled by [Tasks.tsx](../../../src/renderer/src/features/project/Tasks.tsx); parent/child relationships and collapsed state affect visible rows. Verify entry point and names in the real target version.
- **Dynamic source and fallback:** `Navigation.tsx` calls `listAllSessions` for the current `projectPath`. The session catalog in [api.ts](../../../src/renderer/src/api.ts) fetches by project scope, path, and pagination cursor and deduplicates by session ID. An invalid cursor triggers one restart; a failed response yields a gap. Compare task identities, groups, and selection with an independent catalog for this run's isolated project; the page itself is not a reference.
- **Conditional state:** Loading, failure, and empty-state conditions are driven by the current request and visible items. `Tasks.tsx` organizes rows using activity state and parent/child/collapse data. Failure and state matrices are not automatically included in the normal quick review; an empty state cannot be treated as a pass for a non-empty catalog.
- **Side effects:** `listAllSessions` calls `syncSessionRoots` by default, which synchronizes session directories through `syncAuthorizedRoots` in [preload](../../../src/preload/index.ts). Reading the list cannot simply be assumed to have zero writes or no effect on authorized roots. Pinning, reordering, renaming, archiving, and deletion are different state writes or dangerous actions; authorize each separately and verify its real end state.
