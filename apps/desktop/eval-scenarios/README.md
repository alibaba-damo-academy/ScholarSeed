### 盘点与统计口径

本索引是页面、功能及核心流程的导航真源；具体要求、采用依据和适用条件分别回查各页 `requirements.md`、`build.md`，概览不重复定义判据。四类单位分别盘点，映射和去重结论应能回查来源：

| 单位 | 粒度与去重边界 |
| --- | --- |
| 页面 | 按目标制品实际承载的页面或独立设置页计；已确认合并的入口只计承载页，保留原需求映射。一份资产可对应多个页面，不能直接按文件数计。 |
| 功能 | 以独立用户目标或业务能力为盘点单位，关联需求编号和承载页面；同一能力在多个入口出现时核实是否同一能力后去重，不把不同状态或专项自动视为独立完整功能。 |

| 专项 | 按明确对象、状态或平台条件及可观察终态划定检查单元；与基础页面或流程重合时可复用证据，但分别说明范围，不将专项转出已冻结分母。 |

### 单通道提效

只有一个产品Driver时，优先减少操作与LLM之间的反复往返，不以减少检查点提速。建议顺序为：**复用准备 → 冻结检查点 → 连续操作 → 关键状态集中采证 → 集中Judge → 一份报告**。以下是优化建议，执行边界和判定规则仍由执行Skill持有。

| 环节 | 优化方式 | 必须保留的边界 |
| --- | --- | --- |
| 准备 | 首次构建详细分析源码，后续只重读受变更影响的链路；同轮复用已核包身份、基线摘要和公共前提 | 身份或状态漂移重新核验；历史截图不作本轮证据 |
| 操作 | 已观察、明确且安全的导航/表单路径小批连续执行，关键状态再交LLM判断 | 每步保留成功条件，失败立即停止依赖链；不可盲跑或跳过必要反馈 |
| 等待 | 按目标内容、保存反馈或明确错误等待，设有界超时 | 不用固定睡眠代替就绪判断，不把加载中或旧内容当终态 |
| 采证 | 按页面/表单/保存结果等关键状态，一次取齐文字、控件状态、截图及独立参照；同图支持多个检查点 | 瞬时反馈当场采集；截断字段补完整值；行为要求保留真实结果证据 |
| 判定 | 版本、名称、剪贴板和数量等精确事实程序比较；LLM集中判断语义、视觉及需求关系 | 程序结果关联真实产品采集，不用内部写入或预置结果替代操作 |
| 交接 | 每批一份精简证据索引，仅交冻结要求、相关原始证据及必要条件，不反复搬运整段会话/源码 | 不只交Driver摘要或预填结论；关键原值、缺口与来源仍可回查 |
| 报告 | 采证时记录事实，Judge后填结论，一次汇总逐项结果；截图首用展示、后续引用前图 | 不逐功能另建报告或反复润色，不省略预期、实际、判断依据及已知缺口 |

单Driver也可在下一批采证时，由独立Judge评审已完成批次；这属于采证与评审流水线，不是多个智能体同时控制同一实例。若宿主不支持独立并行上下文，则集中采证后串行评审，不虚报并发能力。长批次应按独立页面/工作流交接，避免把全产品证据塞入一个巨大上下文。
