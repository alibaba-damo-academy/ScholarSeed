# Desktop 国际化架构

## Scope / Non-goals

Desktop 使用 `i18next + react-i18next` 提供应用自有文案的国际化能力，首批支持简体中文和英文。覆盖 Electron renderer、Electron main 的应用自有界面、浏览器 renderer、格式化、无障碍文案以及内嵌编辑器的语言衔接。

国际化只负责应用界面文字。用户消息、AI 已生成内容、论文正文、文件路径、代码、用户命名、协议值、日志和原始上游错误保持原文；不改变 AI 回答语言、翻译功能的目标语言、货币币种或用户时区。不引入翻译云服务、运行时机器翻译、远程语言包或第二套语言偏好存储，也不把 UI 国际化放入 Runtime、Adapter 或 Trace。

应用可控的原生菜单、权限说明、启动页和通知属于国际化范围；操作系统自身的按钮、外部网页和第三方应用内部界面不属于应用资源，按各自平台或组件的语言机制处理。

## Source of truth

语言登记、资源、实例和消费边界如下：

| 位置 | 职责 |
| --- | --- |
| `src/preferences.ts`、`src/locale.ts` | 语言模式、`zh/en` 运行时投影与系统语言检测 |
| `src/localization/catalog.ts` | 支持语言、自称、BCP-47 标签、数字/日期 locale、Office locale |
| `src/localization/locales/{zh,en}/*.json` | 按 namespace 保存的中英文消息真源 |
| `src/localization/engine.ts` | 创建配置一致的 i18next 实例、回退和诊断 |
| `src/localization/resources.ts`、`types.d.ts` | 由资源库存生成静态导入和类型契约 |
| `src/renderer/src/app/localization.tsx` | renderer 实例、根 Provider、语言切换和 HTML `lang` |
| `src/main/localization.ts` | main 实例及原生界面文案 |
| `src/renderer/src/components/ui/` | 只消费 `ui` 消息或显式文案 props |
| `src/preferences.ts`、`src/persistence.ts`、preload | 语言偏好的唯一持久化和确认链 |

JSON 是唯一文案来源。`resources.ts` 和 `types.d.ts` 为生成文件，不手工维护第二份 key 清单。语言资源静态导入并随应用离线打包；不在运行时从网络加载资源。namespace 是稳定的领域边界，只有在该领域首次产生产品文案时创建资源文件，不预建空字典。当前实现已装载的基础 namespace 与后续领域 namespace 属于同一资源模型，阶段性未装载不改变 owner 归属。

## Namespace and ownership

Namespace 按业务领域和代码 owner 划分，不按单个页面或组件建立字典。翻译文件物理集中在 `src/localization/locales/{zh,en}/`，消息语义由对应领域 owner 负责。

| Namespace | 负责内容 |
| --- | --- |
| `foundation` | 启动失败、国际化初始化失败和全局基础故障 |
| `ui` | 设计系统原子组件的通用文案和无障碍文字，如关闭、复制、分页和调整大小 |
| `account` | 登录、模型连接、通知、权限、诊断和开发者设置 |
| `shell` | 全局导航、项目/会话菜单、首页、面板、启动界面与应用通知 |
| `conversation` | 会话恢复、发送/重试、模型选择、运行状态、消息外壳和工具动作 |
| `subscription` | 订阅模型连接、登录/断开、模型选择和对应请求/IPC失败 |
| `project` | 项目创建、编辑、选择和移除 |
| `assistant` | 助手面板、上下文、引用和产物展示 |
| `resources` | 资料库、导入、资源树、移动、复制和资源搜索 |
| `literature` | 文献搜索、导入、批处理、详情、摘录和引用 |
| `workbench` | 工作台外壳、Tab、Dock、保存状态、文件操作及Markdown/Monaco/Office应用外壳 |
| `pdf` | PDF 导航、搜索、批注、依据和阅读结果 |
| `tasks` | 后台任务、计划状态、进度和等待提示 |
| `skills` | 技能列表、安装、删除、启停和分类 |
| `native` | main持有的文件/目录选择、保存等原生交互；启动失败归foundation |
| `examples` | 组件示例和设计系统演示数据 |

`foundation` 和 `ui` 保持小而稳定，不放业务错误或领域操作。已有 `components` namespace 只作为迁移期间的兼容容器，保留已经存在的跨业务展示消息；新业务不得新增其 key。迁移完成后按业务子树收紧并删除，不保留转发 key 或重复资源。`examples` 仅供组件示例和测试演示使用，生产业务不得依赖它；示例中的用户内容、文件名和 AI 内容也不属于产品待翻译文案。

跨领域复用按语义 owner 判断：通用交互动作归 `ui`，业务动作和业务状态归拥有该状态的领域，其他领域直接消费该领域 key；不得因为多个页面使用就复制到 `components` 或 `ui`。

React 业务使用 `useTranslation(namespace)` 或 `Trans`；纯 TypeScript 模块显式接收 translator、固定 namespace 函数或格式化器；main 只使用 main 实例；renderer 不导入 main，main 不导入 renderer 资源聚合器。组件不创建 i18next 实例、不读取业务 store，也不保存自己的语言缓存。

## Message design

Key 表达稳定的用户语义，消息使用完整句子和命名参数：

```tsx
const { t } = useTranslation('resources')
return <Alert description={t('import.failed', { name })} />
```

```json
{
  "import": {
    "failed": "无法导入 {{name}}。"
  }
}
```

英文资源保持相同的逻辑消息和参数，但按英文语序表达。禁止按中文词段拆分句子、在页面中维护 `lang === 'en'` 分支或任意拼接运行时 key。

复数按 i18next 的逻辑消息处理。各语言提供自身需要的复数分支；校验逻辑消息、参数和分支覆盖，不要求中英文原始 JSON 叶子 key 逐字相同。

富文本使用 `Trans` 的受控 `components` 和 `values`，只允许代码提供的 React 组件；禁止任意翻译 HTML 和 `dangerouslySetInnerHTML`。

`title`、`label`、`description`、`placeholder`、`aria-label`、Tooltip、Toast、错误、空态和状态提示与普通可见文字具有同等国际化要求。设计系统组件接收文案 props，业务层提供领域消息。

## Errors, status and formatting

可重绘状态保存稳定错误码或消息 ID 及参数，在展示时翻译；不得把当前语言的译文写入业务状态、会话或数据库。后端协议错误码通过类型化显式映射到 UI key；未知错误保留诊断详情并显示应用自己的本地化说明。已知协议错误码通过类型化显式映射到 UI key；未知错误码不得直接拼接成资源 key，应显示通用本地化说明，并将原始错误码和详情保留在诊断区域。

应用生成标签与用户原文共用业务字段时，原标签继续作为业务真值，另携带有限的来源语义；展示层只翻译明确有来源标记的部分。没有来源标记的历史数据原文展示，不能按中文字符串猜测用户命名。语言切换不修改业务标签、模型上下文或选择revision。来源约束见本页下节，不依赖旧提案路径读取。

AI 提示词的中英文默认模板属于 `src/prompts.ts` 持有的可编辑业务内容种子，不是随界面翻译的显示壳。
首次缺失的提示词按产品已确定的初始界面语言填入；持久化的 `selectionPrompts` 始终只有一份。
切换界面语言不改有效旧值或编辑草稿；“恢复默认”只按当前已确认语言替换对应项草稿，用户保存后才经既有偏好写入链生效。
实际 AI 指令继续消费同一份已保存正文；无自动迁移、按内容识别默认值或中英文用户配置双写。

日期、相对时间、数字和金额使用 `createFormatters(language)` 与显式 locale 格式化。语言变化只改变显示格式，不改变币种、精度、时区、排序、检索分词或代码语言判断。

## Label provenance and frozen business identity

来源语义说明“哪些部分由应用生成”，不是另一个翻译服务或任意模板参数。
这是必须保留的取舍：同名中文既可能是默认文案，也可能是用户真实命名；根据文字
猜测会改写用户资产，并让语言切换影响模型输入、幂等摘要或已发送历史。

- 会话 `title_fallback` 与引用 `label_fallback` 属于不同契约；通过同次授权来源观察
  显式映射，不把目录列表制造的默认标签当作历史来源的真实标题。真实非空标题
  与来源标记成对选择，重命名/采纳生成标题同时清除旧标记；不把旧标记附到新标题。
  空来源标题可沿既有规则继承冻结引用；历史缺字段不猜测回填。
- 引用来源的有限值只适用于 session；`selection_source_label` 只适用于带 anchor
  的 selection/literature。明确空字符串与无字段不是同一事实，不截掉真实标题中的
  “划词”后缀，也不根据路径 basename 重建缺失的文献标题。
- 引用解析成功时同时冻结标签与来源字段；失败 issue 继承已有冻结来源，不为展示
  额外读取未授权内容。历史展示使用冻结字段；preview 的当前来源观察与历史冻结
  各有用途，不通过打开预览激活来源会话或修改历史。
- 模型供应商来源只在真实 preset 分支提供 preset 身份；用户 preview_name 即使
  与应用标签同名也不自动翻译。使用已有模型展示函数，未知来源保留原文，不解析
  分隔符、不依赖设置页是否已加载 profile 缓存。菜单分组/布局以当前 Owner 为准，
  不恢复历史提案中的旧组合标签格式。
- 技能分类的 `category_source` 仅标记应用生成的默认来源标签。两个 bundled 编译入口
  显式生成 `builtin` 标记；Serve 在缺失分类时按实际来源补充默认标签，并忽略用户
  元数据中的伪造标记。Desktop 只翻译已标记的默认标签，保留 `category` 业务原文；
  无标记历史分类、自定义分类和未知标记保持原文，不按“系统预置／用户安装”猜测来源。
- 可选来源列沿现有 SQLite Owner additive 保存；旧 NULL 是缺少来源证据，不是
  待回填标签。准入摘要排除 `label_fallback` 与 `selection_source_label`，保留其他
  业务字段和编码；不能因此把任意新增字段都视为可排除。模型卡及模型上下文继续
  使用业务原文，切语言不得 PATCH 选择、递增 revision 或改变 claim/授权。

实际契约与实现分别见[Serve context](../../../../apps/serve/service/platform/context.py)、
[引用解析与摘要](../../../../apps/serve/service/assistant/service/context.py)、
[会话来源解析](../../../../apps/serve/service/chat/service/context.py)、
[Desktop 引用展示](../../src/renderer/src/features/assistant/text.ts)与
[模型展示](../../src/renderer/src/components/business/profile.ts)。修改后覆盖新旧数据、
用户同名标签、来源重命名、空标题、失败/队列/历史/preview 往返，并核对只变展示
语义时摘要和模型字节不变。入口为
[provenance 测试](../../src/renderer/src/features/assistant/provenance.test.ts)及相应 Serve
context/selection 契约；仍需实际语言切换、重启、模型菜单和历史流程验收。

## Runtime and process boundaries

技能引用名称属于展示元数据，不是调用身份。消息流共享仅含名称字段的目录快照，
按账号身份代次隔离；组件重建或同身份目录刷新不清空已解析名称。语言切换立即
使用已有多语言元数据，再刷新目录；迟到响应不得覆盖较新身份、语言或目录代次。
首次目录未就绪时使用本地化技能类型文案，明确缺失或读取失败后才回退原始引用标题。
真实用户标题保持原文，canonical name/path/version、历史记录与模型输入不变。
账号通知监听与 renderer 文档同寿命，避免所有展示订阅卸载后漏掉注销或恢复事件；
重新挂载同步读取当前身份快照，不从默认代次重新开始。

Skill reference names are presentation metadata, not invocation identity. Message streams
share a name-only catalog snapshot scoped to an account identity generation. Remounting
or refreshing the same identity retains resolved names. Language changes project existing
multilingual metadata immediately; stale identity, locale, or catalog responses are rejected.
An unresolved catalog uses the localized skill-type label before a confirmed miss or failure
falls back to the original reference title. User titles, canonical name/path/version, history,
and model input remain unchanged. Account notifications live for the renderer document
lifetime, and remounted consumers synchronously read its current identity snapshot.

启动时，main 读取已确认的偏好并先初始化自身实例；main 只装载自身需要的 `foundation` 和 `native` namespace，不装载 renderer 业务资源聚合器。renderer 使用同一已确认语言初始化资源、设置 `document.documentElement.lang`，再由根 Provider 覆盖页面、Portal、Dialog 和 Toaster。两个进程可以静态导入同一 JSON 真源，但始终各自创建实例。浏览器 renderer 通过既有 bridge 获取偏好，不访问 Electron。

语言切换沿现有偏好写入队列串行提交。持久化、main 投影和 renderer 应用都确认成功后，界面才把目标语言视为已提交；保存失败或应用失败必须使用已提交语言反馈，并支持重试和权威偏好对账。多个窗口不得各自写入语言偏好。

新偏好默认跟随系统，已有 `language: zh/en` 保持固定。跟随模式只保存
`languageMode: system`，不把检测结果落盘；首个可用系统语言以 `zh` 为主标签时使用中文，
其他使用英文，无可用系统语言时才按时区判断，最终兜底中文。macOS 和 Windows 都从
Electron 获取系统语言列表，Web 使用浏览器语言列表。跟随模式在启动和主窗口重新聚焦时
读取语言，不轮询、不重载页面、不改写偏好。存在未保存的 Monaco 编辑时跳过自动切换，
待处理后下次聚焦再检查；手动切换继续走原确认与保存流程。
预览等显式语言快照与真实新配置分开构造，固定语言不携带系统模式。
聚焦刷新失败沿既有偏好错误提示提供重试；应用失败尝试恢复旧投影，未恢复的刷新
阻止退出确认，重试仍受脏编辑保护且不写盘。成功的显式偏好提交也可恢复同步。

通知已投递内容不追溯改写；新通知使用已确认语言。打开的系统对话框不因切换强制关闭，下次打开使用新语言。

## Editors and native surfaces

[Monaco frame 宿主](../../src/renderer/src/features/workbench/monaco/host.tsx) 使用
同源构建入口与当前偏好语言，ready 消息必须同时匹配 iframe Window、origin、消息
类型和本次随机 token；切换/卸载清理监听及 frame 引用，不能只凭 origin 接纳旧
实例。[frame 入口](../../src/renderer/src/features/workbench/monaco/frame.ts) 在加载
runtime 前安装 NLS，当前 query 非 `zh` 时归一为 `en`，不是拒绝一切非法 query 的
验证器。iframe realm 隔离用于 NLS 生命周期，不是跨源安全沙箱，也不能将 iframe
DOM 挂回父窗口绕过焦点/选区所属 Window。

Office 保留自身 gettext/WASM 资源和语言机制，应用只传 `catalog.ts` 登记的 `zh-CN` 或 `en-US`。Monaco 的 NLS 文案在模块求值时固化，因此每个已挂载代码 viewer 由同源 iframe 独立持有 Monaco 模块图；语言提交成功后只重建这些 frame，并从现有文档 session 与 view state 恢复文件、光标、选区和滚动位置，应用 renderer、当前页面、项目和标签不得重载。没有未保存的 Monaco 文档时直接提交偏好并重建 frame；存在未保存文档时必须先明确确认并仅保存 Monaco-backed 文档。保存失败、外部冲突或仍有 dirty Monaco 文档时不得提交语言。普通 Chromium 重载快捷键继续禁用，语言切换不得拥有 renderer reload IPC。编辑器实例必须记录实际 locale，不能复用旧语言运行上下文。

主进程原生菜单、启动页、权限说明和原生通知由 `native` namespace 与 main 实例负责。第三方编辑器和操作系统缺少对应资源时，应明确记录支持边界，不把回退或外部界面冒充为完整翻译。

## Validation constraints

资源检查必须验证语言登记、namespace、key、插值参数和复数分支；生成文件必须与 JSON 库存一致。源码检查限制新增可见硬编码和旧字典消费者，且覆盖 JSX 文本、展示属性、Tooltip、反馈调用和显式展示字段。

`fallbackLng` 只用于启动故障和可观测降级，不构成正常业务文案覆盖。发布检查对纳入范围的 namespace 要求目标语言零缺失、零 fallback；缺失译文必须诊断并阻断发布。

发布范围由当前生产路由和页面、main 原生菜单/启动页/权限/通知，以及所有由生产入口加载的业务组件组成；`examples`、测试 fixture、协议详情、用户内容和外部页面不计入产品文案范围。静态门禁只能证明资源与调用契约，不能证明真实界面覆盖；发布范围还必须通过真实 Desktop 或浏览器产品流程验证语言切换、Portal、Toast、错误、设置、工作台和编辑器边界。

## 正反例

```tsx
// 正例：领域组件直接消费语义 namespace。
const { t } = useTranslation('resources')
return <Alert description={t('import.failed', { name })} />
```

```tsx
// 反例：页面维护语言分支或保存译文。
return <span>{lang === 'en' ? 'Import failed' : '导入失败'}</span>
setError(t('resources.import.failed'))
```

## Enforced by

`pnpm ops ci test integration --scope tooling --suite i18n` 和 `pnpm ops ci check i18n` 校验资源、生成结果、调用参数、复数和可见源码债务；`pnpm ops ci check types desktop` 校验类型化 key 与参数。`pnpm ops ci check docs desktop` 校验本文结构和链接。上述门禁不替代真实产品流程，真实双语验收必须在所属产品入口完成。

## Update triggers

只有在改变语言登记、资源加载方式、实例边界、偏好确认语义、namespace ownership、编辑器语言衔接或校验契约时更新本文。新增业务文案只需在对应 namespace 的中英文资源和消费代码中实现，不在本文记录实施进度、执行计划或方案比较。

## Stop condition
