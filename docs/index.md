# Project Knowledge Index

This page maps task intent to the current Owner, governing rules, and verification entry points. It is not the source text itself or a claim that the whole repository has been accepted.
Start with the loaded root [AGENTS](../AGENTS.md) and applicable local rules. When a direct Skill or Owner link is available, read it directly instead of traversing this page for every task. Add affected parties only when a cross-Owner contract changes. If rules and implementation conflict, verify why; do not automatically relax security requirements.

## Reading and Maintenance Boundaries

When the symptom is clear and you need a fine-grained rule, consult [diagnostic and topic routing](runbooks/triage.md). It only points from problems to existing Owner source documents; it does not duplicate mechanisms and is not required reading by default.

This index maintains Owners and reading conditions; it does not copy mechanisms, long command procedures, or one-off acceptance results. Stop expanding after confirming the source document; add a bounded entry when a new issue arises. See the [knowledge rules](architecture/knowledge.md) for ownership, update principles, and governance-check scope.
The actual findings and exclusions for root `docs:check` are defined by the [check contract](architecture/knowledge.md#当前检查范围). Structural checks do not prove source-text semantics, host behavior, or real product acceptance.

- If no matching requirements or evaluation document exists, state the gap and have the responsible Owner add one when authorized. Source code alone does not establish a product goal or acceptance; do not pre-create empty domain pages.
- This index does not prove that historical proposals, research, or daily reports have been migrated, that all domain semantics have been verified, or that every repository link has been checked. Explicit file-structure checks and local Desktop gates have their own scopes and do not replace semantic, real-host, or migration acceptance.
