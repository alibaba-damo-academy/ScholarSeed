# Session Events and Model-Bridge Stream Criteria

Use this page when troubleshooting abnormal model-stream endings, long waits, tool-input conversion, or event aggregation. The implementations belong to [completions](../../apps/serve/service/chat/service/completions.py) and [streams](../../apps/serve/service/chat/service/streams.py), respectively. Data collection and attribution procedures are maintained only in the [Engineering guide](../../packages/damoatrace/README.md); CLI workflows are not duplicated here. This page describes mechanisms and criteria. It does not authorize reading user content, changing retry policy, or starting product acceptance.

<a id="产品会话事件续流与取消"></a>
## Product Session Events, Stream Continuation, and Cancellation

<a id="授权等待与跨轮次续跑"></a>
### Authorization Waits and Continuation Across Turns

[SessionInteractions](../../apps/serve/service/chat/runtime/interaction.py) explicitly publishes the session lifetime. A reply restores the running state only when the native turn still matches and the product is running or waiting; it cannot revive a completed turn. [Desktop HIL](../../apps/desktop/src/renderer/src/hil.ts) and the [live projection](../../apps/desktop/src/renderer/src/live.ts) retain session authorization on normal completion, while interruption still cleans it up. A card being answerable, authorization being resolved, and the model executing are three different facts.

The [full-text gate](../../apps/serve/service/literature/api/gate.py) captures the submission, task type, context revision, and interruption generation. While the same turn is still active, it returns the original wait result; only after the original turn completes normally does it submit a stable continuation ID under the authorization policy. Whether a rejection may fall back is determined by the owning checkpoint policy; do not generalize one task type's rejection continuation into permission for every task to bypass full-text authorization. Within the lifecycle lock, [TurnService](../../apps/serve/service/chat/service/turns.py) rejects continuation when its source has been superseded by a new submission, queue, permission intent, or interruption generation. Do not create unconditional resends in business routes. An HTTP disconnect is different from a user stop; this mechanism does not prove that an authorization wait will automatically recover after process restart.

Waits at the same checkpoint are held by a shared background task, so cancelling an HTTP request does not revoke that product interaction. A user stop must still terminate the related wait and continuation. A stable continuation ID deduplicates the same decision; it does not authorize a new submission or guarantee recovery of a persistent background task. When changing this behavior, also check duplicate requests, disconnects, stops, completion of the original turn, and late replies so that transport cancellation is not mistaken for user rejection or re-execution.

Targeted evidence is the repeated-wait, request-cancel/stop, and post-normal-completion continuation coverage in the [full-text gate contract](../../apps/serve/tests/contract_fulltext_gate.py). Controlled RecordingTurns do not prove that a new real-model turn succeeds. Acceptance must observe the card, real turn, rejection path, and final state together; showing “正在思考” (the UI text “Thinking”) again is not sufficient.

<a id="权限选择意图与原生生效确认"></a>
### Permission-Selection Intent and Confirmation of Native Application

[Serve SessionService](../../apps/serve/service/chat/service/sessions.py) separates the persisted selection from the value currently applied live, and updates active state only after an APPLIED acknowledgment. ACCEPTED, a warning, or a query response does not mean the current turn has applied the setting. [Codex process](../../packages/adapters/codex/scholarseed_codex/process.py) distinguishes confirmation of thread settings from reviewer updates for the current turn and checks connection/attachment generations. If the thread setting is confirmed but the turn setting is not applied, the scope for the next turn is retained. Determine whether a warning exists from the actual acknowledgment; do not conflate targetUnavailable with an unknown error. Unknown outcomes must not be retried automatically or falsely reported as a hot switch. [Adapter session](../../packages/adapters/codex/scholarseed_codex/session.py) uses the startup projection to decide what can be applied; do not describe every sandbox, profile, or platform change as a reviewer hot switch.

Changing modes does not automatically answer existing HIL requests or expand existing authorization. If the setting cannot take effect in the current turn, the user must explicitly choose the next turn, cancellation, or continuation after interruption. The last option still requires checks for a real terminal state, original thread identity, and stale sources; HTTP admission does not prove continuation completed. The mocked RPC in the existing [permission contract](../../tests/contract_permission.py) is not acceptance of the current Codex experimental API or of both platforms. Tests use native confirmation and identity evidence; do not infer permissions from button labels, cached selections, or historical success counts. Real verification must preserve the renderer's authentication context. An isolated test must not change model credentials by opening a session as another owner and then attribute the result to recovery.

### Trustworthiness of Subagent Progress and Boundaries on Unresolved Content

[Codex process](../../packages/adapters/codex/scholarseed_codex/process.py) projects item boundaries and stream activity only for an attributed child thread. The [router](../../packages/adapters/codex/scholarseed_codex/router.py) throttles non-boundary activity, rejects progress after a terminal state, and keeps a bounded snapshot for summaries. A wait timer and parent-session activity do not prove that a particular subagent is still healthy. If no public summary is available, wait truthfully; do not poll the full transcript or manufacture heartbeats. The degraded description `SUBAGENT_CONTENT` does not mean full child-thread transcript support.

Distinguish the intended restriction from current source: `subagent_item_summary` in [activity](../../packages/adapters/codex/scholarseed_codex/activity.py) also collects the command, aggregatedOutput, and exit_code for commandExecution; status payloads may include bounded tool input/result, and the [Desktop transcript](../../apps/desktop/src/renderer/src/transcript.ts) receives these fields. Therefore, do not assume that every `public_summary` or every bounded payload contains only public reasoning summaries, and do not repeat the old proposal's guarantee that tool input/output is not displayed. How the current implementation relates to that stricter content restriction still requires Owner/security review. The stricter restriction in documentation does not authorize broader disclosure or a change to the product projection policy.

Real acceptance must separately cover attribution, stages/terminal states, snapshots after throttling, reconnect deduplication, HIL ordering, and waiting when no summary is available. Screenshot claims for historical models/platforms do not carry over as current acceptance; UI clocks or the existence of source projections cannot replace event/Trace evidence and real-product evidence.

### Visible Audit History and Model Recovery History

`rejected_turns` in the [persistent-event Owner](../../apps/serve/service/chat/persistence/events.py) identifies a whole turn only from persistent `turn_failed` and an explicit content-rejection code; ordinary service failures or unavailable review are not content violations. `portable_history` keeps product-visible records by default. Only explicit `exclude_rejected=True` excludes the user and assistant messages from those turns. Do not delete UI audit records to isolate context, and do not rely on a model's promise to “forget.”

The [activation composition](../../apps/serve/service/chat/runtime/composition.py) checks persistent rejection records for the currently bound thread, and when necessary suspends it, opens a new session, and passes filtered portable text history. A service-tool profile change may also trigger rebinding; do not attribute it to content rejection based only on a log name. The [catalog Owner](../../apps/serve/service/chat/persistence/catalog.py) performs compare-and-swap rebinding using the old binding identity only after Provider initialization; on conflict it does not overwrite the updated binding, and the transaction preserves product events. The [Adapter](../../packages/adapters/codex/scholarseed_codex/session.py) seeds initial history after native open and closes the candidate on failure. Text recovery does not undo file operations and does not mean internal tool state is restored.

[History retrieval](../../apps/serve/service/chat/service/history.py) uses a filtered projection for branches with visible product messages. When there is no visible projection, catalog fallback remains; do not extrapolate from one branch and claim that isolation has been proven for every history source. Deterministic evidence is in the rejected-history and atomic-rebinding cases of `tests.contract_product_events` (run with the project Python from `apps/serve/`). Real acceptance still requires evidence from native threads/injection protocols, preservation of normal facts, isolation of rejected topics, and restart recovery; neither model self-report nor SQLite unit tests can replace it. Historical private-gateway review budgets and deployment status are not current capabilities of, or authorization for changes to, this repository.

Session SSE enters through the [HTTP route](../../apps/serve/service/chat/api/sessions.py) and [EventService](../../apps/serve/service/chat/service/events.py). Product runtime state and broadcasts belong to [LiveSession](../../apps/serve/service/chat/runtime/live.py); Desktop connection and projection belong to [api](../../apps/desktop/src/renderer/src/api.ts) and [live](../../apps/desktop/src/renderer/src/live.ts), respectively. These product events differ from the model-bridge SSE below; do not mix their sequence numbers, terminal states, or recovery criteria.

- Current broadcasts expose only committed product events; each subscriber has its own bounded queue. The queue is a wake-up notification, not the sole source of event order or content. EventService registers the subscription first, then replays pages from the persistent event source starting at `from_seq`, and continues reading committed records. When a queue fills, the slow subscriber is removed and its stream ends. Do not reintroduce competing consumption from a shared queue or treat descriptions of the old in-memory backlog window as the current persistence contract.
- Desktop explicitly rebuilds EventSource from the last successfully projected seq, ignoring overlapping replay and old connections. It validates schema, session, and contiguous sequence numbers. A projection failure does not advance the cursor; a sequence gap starts recovery. A heartbeat proves observable connection activity, not task completion. Recovery callbacks for silence, returning to the foreground, or projection errors differ from ordinary transport reconnection. Verify the live snapshot and state-merge path to establish complete recovery; API stream-resume code alone does not prove that restart causes no data loss.
- The end of a content block is not the end of a product turn or session. Desktop projects named product terminal states such as `turn_completed` and `turn_interrupted`; do not substitute model EOF, body deltas, or the old `turn_end` signal. A disconnected connection likewise does not prove the background task has ended.
- The actual stop endpoint is `POST /api/serve/sessions/{session_id}/interrupt`, which invokes runtime behavior through [SessionService](../../apps/serve/service/chat/service/sessions.py). Runtime ACCEPTED/APPLIED acknowledgments do not independently prove that the provider task and background process have both exited. Check the product terminal state and cleanup evidence from the relevant execution Owner. Evaluate failure responses, idle/resource-wait branches, and genuinely active turns separately; HTTP success or `interrupting: false` does not prove everything stopped.
- Interruption also cancels product interaction requests and expires pending HIL requests individually, then broadcasts `hil_resolved`. Clearing frontend cards only by turn is insufficient for permission requests whose turn identity differs. Session termination has separate queue cancellation and lifecycle locking; do not treat terminate and interrupt as the same operation.

These boundaries preserve the reasons for historical failures: incorrect terminal states once masked missing lifecycle projections; competing consumption and reconnects without cursors could miss completion/HIL; a stop button changing appearance did not prove that backend cancellation worked. Historical WorkSession, agent_started/agent_done, and old interface names are not evidence of current implementation.

<a id="中断后的原生终端回收"></a>
### Native Terminal Cleanup After Interruption

The active-turn stop branch in the current SessionService explicitly passes `cleanup_background_processes=True`, while the [Runtime request](../../packages/runtime/scholarseed_runtime/contract/command.py) defaults this intent to off. This differs from the old scope of “cleanup only behind the full-text authorization gate; ordinary stop unchanged.” Do not infer from the old proposal that ordinary stops will not clean up processes, and do not use the implementation to relax confirmed requirements unilaterally; the product Owner must confirm any scope change. Before interruption, [Codex turn](../../packages/adapters/codex/scholarseed_codex/turn.py) captures active command-item identities, matches them against the native background-terminal list, and terminates by native processId. This is not an OS PID or whole-thread cleanup. It waits for bounded confirmation that the turn has completed and the matched terminal has disappeared; an empty item set returns immediately. Therefore, one acknowledgment cannot establish that arbitrary unknown background processes have exited. Protocol errors and timeouts remain failures; do not fake safe recovery by deleting permission cards, skipping gates, or clearing state.

Targeted verification entry points are the [product-event contract](../../apps/serve/tests/contract_product_events.py), [interrupt-barrier contract](../../apps/serve/tests/contract_interrupt_barrier.py), and [Desktop stream-resume test](../../apps/desktop/src/renderer/src/stream.test.ts); use the applicable suites selected by their owning runners. After changes, also run real product flows for disconnect/recovery, interruption, and HIL. Source inspection, knowledge migration, and contract tests do not prove that the fault passed final product acceptance.

## Public Reasoning Summaries in Agent Conversations

For answer sources, also see [Answer metadata and citation evidence](#回答元数据与引用证据). Model identity, public summaries, search facts, and citation locations cannot substitute for one another.

This path differs from single-shot reasoning such as literature translation. [Adapter session](../../packages/adapters/codex/scholarseed_codex/session.py) requests summary auto under the `PROVIDER_NATIVE` tool protocol and handles that separately from the user's effort setting. Do not equate a subscription model with NATIVE transport or promise that every model will provide a summary. [turn](../../packages/adapters/codex/scholarseed_codex/turn.py) marks `summaryTextDelta` as a public summary and preserves part indices while ignoring raw `textDelta`; an empty part-added event marks a segment, not the first non-empty summary or a model token.

The [Runtime projection](../../packages/adapters/codex/scholarseed_codex/events.py) preserves the reasoning role. [Serve live](../../apps/serve/service/chat/runtime/live.py) publishes reasoning deltas and completion events to the product only when they have an explicitly public source; it does not mix the body-accumulation path into summaries. This reuses existing ordering, persistence, and replay instead of adding summary-specific storage or polling that creates a second terminal state. Do not automatically treat provider `reasoning_content` as a public summary.

[Desktop transcript](../../apps/desktop/src/renderer/src/transcript.ts) locates thinking by turn/item and rejects completed items and duplicate/old sequence numbers. A change in part index appends a separator for a non-empty summary; an empty delta does not create a content item. Item completion and turn completion are different facts; a completion event with no initial delta is not guaranteed to create a visible summary. Historical replay reuses the projection; actual collapse, focus, and cancellation still require product acceptance.

When troubleshooting, distinguish an upstream absence of public summaries, transport latency, and UI presentation. Status animation must not pose as a reasoning stream; do not manufacture success by increasing effort or simulating typing. Latency metrics distinguish acceptance, first non-empty summary, first body content, and completion time. Do not attribute an overall reasoning-speed improvement to a small number of historical samples or earlier UI feedback. Targeted contracts are [transcript](../../apps/desktop/src/renderer/src/transcript.test.ts) and [activity](../../apps/desktop/src/renderer/src/activity.test.ts); they are not evidence of current real-model acceptance.

## Answer Metadata and Citation Evidence

[ModelRun](../../apps/serve/service/chat/provenance.py) stores the provider, selected model, and upstream-reported actual_model_id for that run; it does not read current settings to add labels to an old answer. [LiveSession](../../apps/serve/service/chat/runtime/live.py) updates the snapshot only for a response matching the active product turn and projects it into the message by native turn. [EventService](../../apps/serve/service/chat/service/events.py) decorates history from original message events by turn/item; when reliable records are missing, the value remains unknown. If the upstream does not report an ID, explicitly fall back only to the ID selected for that run. A model's self-report, version probe, or provider name does not prove which model actually ran. Do not add connection addresses, credentials, or request bodies to metadata. Real acceptance checks live labels, old answers after switching models, and reopened history; the existence of a static snapshot does not prove that the UI passed.

[Source projection](../../apps/serve/service/chat/service/sources.py) distinguishes source identity, explicit numeric aliases, and positions where text appears; conflicting aliases are not bound, and citation numbers are not guessed from search-array indices. The range in [native provenance](../../apps/serve/service/chat/service/provenance.py) is bound to an item and exact answer revision, converting Unicode source ranges to UTF-16. Missing, empty, invalid, and over-limit annotations are distinct states. A Provider returning sources does not mean page content was verified page by page. A URL or citation number alone does not prove that an answer is correct, that a source was searched, or that a PDF receipt was located successfully.

The old proposal's statements “do not upgrade to searched without search facts” and “bare URLs always remain ordinary links” are not universal guarantees in the current implementation. Source projection also accepts explicit numeric/reference entries or matching native annotations, and may return an empty search_id with pending coverage; `kind: searched` by itself does not prove that a search ran. The `isCitationLink` function in [Markdown citations](../../apps/desktop/src/renderer/src/components/markdown/citations.ts) also recognizes matching URL text, not only numeric labels; [decorate](../../apps/desktop/src/renderer/src/components/markdown/decorate.ts) uses it to mark display nodes. The Owner must check the applicable product requirements against current behavior. Do not use migration approval to expand trust or remove the requirement to preserve ordinary links. Verify original text, copied text, selection positions, and display AST separately; do not rewrite old history to fabricate missing aliases or evidence. The [source contract](../../apps/serve/tests/contract_answer_sources.py) proves only parsing/projection branches. Streaming, emoji/CRLF, ordinary links, source popovers, receipts, and reopened sessions still require real-product verification.

## Observation Surface and Terminal State

<a id="来源候选交付与事实核验"></a>
### Source Candidates, Delivery, and Fact Verification

Search candidates, citations proactively declared by an answer, and associated evidence are different states. A tool's `tool_declared` acknowledgment does not prove provider execution; its description cannot be treated as verification evidence. [coverage](../../apps/serve/service/chat/service/coverage.py) rereads pages for these candidates. Other actual search excerpts may be reused with an explicit origin; fetch failure does not fall back to a tool-declared summary. A low-trust declaration for the same URL cannot replace an existing real source; a missing candidate and an explicitly empty set are not interchangeable.

[SearchService](../../apps/serve/service/chat/service/search.py) reuses Invocation. A non-native path requires the unique final artifact explicitly published by a successful terminal state and reads it through the existing artifact API; a native path must observe a real search event. An arbitrary stdout, script path, or URL cannot stand in for a restricted profile, query, or parent PermissionIntent. Check the actual turn identity before and after invocation and when registering it. This avoids losing sources when the parent model truncates stdout; it is not a guarantee of better search quality or latency. Do not equate internal task cancellation with termination of provider execution.

Source verification binds fixed original-text snippet IDs to UTF-16 ranges, rejects missing/duplicate IDs and mismatched `evidence_quote`, and does not let the model rewrite body text to obtain locatable citations. Keep `page_claim`, `search_observation`, and `advice` separate: a limited search with no result does not prove a webpage does not exist, and the latter two cannot claim support from page facts. A declaration, matched snippet, or coverage state is not authentication of truth. Bounded page/model verification must still preserve public-network reading and untrusted-data boundaries. An implicit Agent fallback cannot replace a strict no-tools request; when the requested capability is unavailable, state clearly that it cannot be verified.

After verification, [LiveSession](../../apps/serve/service/chat/runtime/live.py) rechecks pending settlement, interrupt generation, and closed state before merging the current source projection. A late result must not be written to a new turn or overwrite an already confirmed position. Real verification is still required for timeouts, cancellation, recovery, late sources, ordinary links/code/tables, original and copied text, source popovers, and reopened history. Passing with an old session or unit tests does not prove current cross-platform product acceptance.

### Retry Window for Transient In-Stream Failures

Native stream pre-reading in [completions](../../apps/serve/service/chat/service/completions.py) uses a shared attempt budget only when no semantic output has yet been observed for the request, pre-reading confirms an error, and the normalized error code is in the [rejections allowlist](../../apps/serve/service/chat/service/rejections.py). The old response is closed first; prefixes from failed attempts are not replayed downstream. Cancellation or revocation must not trigger another resend. [StreamObservation](../../apps/serve/service/chat/service/streams.py) treats unknown events, invalid JSON/non-object values, and events outside the safe set as semantic boundaries; it also stops pre-reading when the buffer limit is reached. Do not infer retryability from HTTP 200, a small event count, or free-form error prose, and never have the renderer replay tools automatically.

Verify failures before HTTP headers, failures inside a native Responses stream, and product-level whole-turn retries separately. This branch does not guarantee replay for arbitrary provider streams or requests that may already have side effects. `stream_retries` in diagnostics is the evidence for in-stream attempts; do not infer it from UI copy. A deterministic entry point is `test_native_stream_overload_retries_only_before_semantic_output` in the [completion-bridge contract](../../apps/serve/tests/contract_completion_bridge.py). A controlled upstream does not prove that the real model service recovered, that the product succeeded, or that users perceived a speed improvement.

<a id="原生观察接收投影与临时暂存"></a>
### Native Observation Receipt, Projection, and Temporary Staging

[Adapter mailbox](../../packages/adapters/codex/scholarseed_codex/mailbox.py) stores normalized observations under a byte budget and spills overflow to a same-process private temporary FIFO. Do not use pickle staging as untrusted input or as a restart-recovery format. While a disk backlog exists, new records do not overtake it; events are neither merged nor dropped. Serialization/disk failures are latched and wake the consumer; do not publish a successful terminal state after observations were missed. [Session receipt](../../packages/adapters/codex/scholarseed_codex/session.py) advances the watermark only after admission completes, finishes admitted I/O during cancellation, and prevents safe suspension while records remain unconsumed. Explicit close abandons the temporary backlog; it does not mean normal completion projected everything.

[Gateway driver](../../packages/runtime/scholarseed_runtime/gateway/driver.py) collects only bounded batches that are already ready; it does not wait for a batch to fill. It waits for projection first, then reduces events and advances the projection sequence. [LiveSession](../../apps/serve/service/chat/runtime/live.py) batches only eligible consecutive primary-tool progress events; a change in identity, byte budget, or another observation forms a boundary. The [serial persistence worker](../../apps/serve/service/chat/persistence/worker.py) propagates cancellation after committed I/O completes; broadcasts occur only after product transactions and per-event Trace work complete, and sequence gaps fail explicitly. These mechanisms differ from SSE subscriber queues. Do not bypass backpressure by enlarging queues, using unbounded memory, or skipping events before completion.

The [mailbox contract](../../tests/contract_codex_mailbox.py) covers FIFO ordering, failures, cancellation, and close. The [real-pipe integration](../../tests/integration_observation_drain.py) still uses a controlled consumer; it is not real Desktop/model acceptance. Troubleshooting must measure receipt, persistence, broadcast, and UI latency separately, and verify complete bytes, sequence numbers, and terminal ordering. Old P95 results, macOS recordings, or guesses based on Windows icacls are not current evidence of improved performance.

- `request_id` associates one bridge request. Distinguish the original user-message identity, requested model, and actual routed model; do not replace the identity captured at entry with whichever turn is active at completion. Use the current diagnostic-field Owner for retry/connection statistics.
- Upstream observation records received SSE; downstream observation records non-empty body frames returned successfully by ASGI `send`. Time spent waiting for `send` is an observation made by this bridge; it does not prove that Electron/Codex or a remote consumer parsed the frame, nor does it independently prove a network bottleneck. Upstream-read time may be affected by downstream backpressure; attribute it only with cross-end evidence for the same request.
- HTTP 200, EOF, `[DONE]`, cancellation, and a real Responses terminal event are not the same signal. A consumer may close the connection after receiving a terminal event. Check terminal, error, and end_reason together; do not infer failure from cancellation alone or success from an HTTP status without an error.
- If a native stream emits `error` without a Responses terminal event, the bridge preserves the error and emits a controlled `response.failed`; it does not wrap an existing failure again. EOF without a frame does not fabricate completed, approval success, or tool success. Provider errors, transport errors, and internet unavailability must not be substituted for one another.

## Aggregation Is Not Protocol Downgrade

Text deltas may be aggregated when they are consecutive, have the same target, and their fields can be handled safely. Body and reasoning target indices are distinguished by `content_index` and `summary_index`, respectively; do not merge across targets, types, or unsafe frames. Named constants in streams own size, time, and buffer limits; do not duplicate their numeric values in this document. Verify ordering, SSE metadata, and sequence mapping against the actual batcher; do not discard semantics to reduce event count. Fewer events may result from aggregation, but do not prove end-to-end speedup. Aggregation does not change the publication policy for raw reasoning.

CompletionStream registers cancellation ownership on the actual `stream_response` consumer task and clears it on exit; do not mistake the pre-read `anext` task for the whole response consumer. On exit, the aggregator first cancels and awaits unfinished pre-reading, then closes the source generator. Close the source even when pre-reading has already completed; do not delegate `finally` cleanup to garbage collection. A normal Exception first emits cached text and then propagates unchanged; cancellation and generator close do not flush. This does not turn an upstream failure into success. When merging same-target frames, preserve the first event name and the order of other id/comment fields; remove only later duplicate `event` lines. Do not discard the entire header block to reduce event size.

Remove the one `additional_tools` input item in Responses Lite at its actual position; do not rename it into an ordinary message. If there is no explicit top-level `tools`, project the item's tool definitions. If top-level `tools` is present, use the current request's tool set, including an explicitly empty list; do not merge tools from before a model switch. When these differ, record `superseded_tool_declarations` in conversion diagnostics. Reject before sending if there are multiple declaration items, invalid roles or definitions, conflicting definitions with the same identity in one declaration set, or another input refers to that declaration identity. Preserve the order of other messages and request settings. Names for `function`, `custom`, and `namespace` must be non-empty and not whitespace-only. Do not construct identities for anonymous native tools using an empty name; preserve their original declarations and let the relevant upstream protocol validate configuration constraints. A tool definition being convertible does not mean the upstream supports every type or grammar. Do not delete schemas/tools to fake compatibility. Model-alias routing also does not automatically change native model-capability metadata.

## Privacy, Evidence Gaps, and Verification

<a id="provider-失败语义与可重试性"></a>
### Provider Failure Semantics and Retryability

[Codex failure Owner](../../packages/adapters/codex/scholarseed_codex/failure.py) unwraps error frames at the vendor boundary, normalizes controlled codes/HTTP statuses, and generates stable safe messages. It does not forward request IDs, links, or transport envelopes. Unknown semantics receive an explicit generic error; do not guess quota state from natural-language text to trigger permission escalation. Native `willRetry` belongs to the vendor retry lifecycle; it is not permission for the user to resubmit.

[Serve ledger](../../apps/serve/service/chat/runtime/ledger.py) projects explicit retryability. `user_retryable` and compatibility with missing fields in historical records may produce a retry flag; other terminal states must not be treated as transient network failures. [Desktop failure](../../apps/desktop/src/renderer/src/failures.ts) classifies known codes first and retains an old-copy fallback. Authentication failures have their own continue action; do not repeat the old description that authentication failures have no action entry point at all. Nor does the existence of an action button prove that credentials are fixed or a retry succeeded safely.

[Trace emitter](../../apps/serve/service/chat/runtime/evidence.py) explicitly maps Runtime terminal states: failed/unknown to error, interrupted to cancelled, and completed to ok. Product turn_unknown still maps to unknown; do not merge these two kinds of records into one state. An unsupported-notification incident is not a whole-turn failure. Standalone Trace queries determine events from top-level status; `run.outcome` has its own controlled meaning. Do not have the Trace package recognize Serve event names to fabricate status, and do not rewrite historical JSONL. A successful query or HTTP 200 does not prove the upstream turn succeeded.

When changing this behavior, check the [Adapter contract](../../tests/contract_codex_adapter.py), [Trace projection contract](../../apps/serve/tests/contract_trace_evidence.py), and current Desktop error-classification consumer. Then verify consistency using a real product error card, native failure event, and Trace query. Test source, old incidents, or a single failure list cannot replace real-model and post-restart recovery acceptance.

Routine observations store only restricted metadata, shapes, and fingerprints; they do not store normal model body text, input text, tool parameters, or original request headers. Fingerprints and shapes are not risk-free, so do not copy complete identity/fingerprint lists into public reports. Error summaries are bounded and redacted; known outbound credentials are filtered by Redactor and URLs are cleared. The Owner defines these limits. Invalid, oversized, and unterminated events are evidence gaps; do not invent missing data. Observation buffers must not block or alter forwarding of the original stream. Detailed authorized body content and exports follow the separate product diagnostic boundary; see [Trace-consumption constraints](../architecture/ownership.md#trace-消费与诊断正文).

After protocol changes, cover safe aggregation/pass-through, prefix conflicts, errors/EOF/cancellation, and privacy rejection. Contract checks do not replace real product streams. Record the actual platform and final code; acceptance on one platform does not prove acceptance on the other.
