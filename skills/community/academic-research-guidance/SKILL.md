# Academic Research Guidance

**English** · [简体中文](SKILL.zh.md)

Apply this skill to the research portion of the current request, not unrelated
tasks merely sharing its vocabulary or tools. Inspect relevant user-provided or
referenced materials and prior answers before deciding anything is missing.

## Check intent, then load only needed detail

Apply all five judgments to every research request before substantive work:

| Judgment | Check |
| --- | --- |
| Sense | Is each concept's meaning fixed by this context? Do not broaden or narrow it. |
| Relations | Preserve bound phrases. Distinguish a combined subject from parallel topics; bare juxtaposition or overlapping fields joined by "and" can leave a real fork. |
| Premise | Does the field itself name two materially different camps, with neither selected? Name both before treating this as a fork; breadth alone is not one. |
| Mode | Is the intended deliverable clear? Several ways to produce the same deliverable do not make the user's intent ambiguous. |
| Scope | Is the focus sufficient for that deliverable? Preserve explicitly chosen breadth; never narrow against the user's will. |

Ask only about seriously plausible readings that would materially change the work,
even when one is much more likely. Do not manufacture forks. Unresolvable terms or
a missing research topic need confirmation, not invented facts; a broad topic is valid.
A fully-specified request asks nothing and routes immediately. Preserve previous
answers; changing skills alone does not reopen them.

Before asking about an unresolved fork, or when unsure how to apply these judgments,
read [clarification](references/clarification.md). It owns question order, available
mode choices, the one-item-per-turn interaction and reply handling. Otherwise skip
that reference. Before key research conclusions, read [evidence](references/evidence.md),
not for greetings or clarification alone. Read one language version, not both;
reuse unchanged guidance still in context and reread after change or context loss.

## Respect task ownership

This skill supplies shared research guidance, not a research deliverable or a
mode option. Never route back to itself. Select available task skills by their
actual scope and exclusions and the work needed for the intended outcome, not
just the final format. Use a matching skill or necessary ordered composition;
cost can choose among matching paths, not erase coverage. General capabilities
are a direct path only when no available skill covers an explicit deliverable
and the agent can complete it. Being able to use general tools is not that proof.

Carry a faithful intent statement into the selected skill's workflow: preserve
the motivating problem, bound relations and every concrete user constraint;
add nothing the user neither stated nor delegated. Check both for omissions and
unsupported additions. Keep this internal, briefly tell the user what will be
done, then follow the selected skill(s) in order; do not invent a skill-call API.

The selected task skill owns its stages, modes, checkpoints, authorizations,
and recovery. Intent clarification is not authorization to start, download,
or publish. Do not reproduce or override those protocols here.

Keep internal classification and routing reasoning private, while still explaining
evidence limits and any user-facing execution modes, costs, or confirmations the
task skill requires. Follow the host's current search restrictions; loading this
skill does not authorize external retrieval.

When the user switches to a nonresearch task, stop applying research-specific
clarification and conclusion formatting. Previously read text may remain in the
conversation history; its presence does not make unrelated tasks research.
