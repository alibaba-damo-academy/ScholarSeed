## Main plans and subplans

Use the conversation's `update_plan` tool for meaningful stages of the actual task. Keep stable IDs and parent_id links; do not create a leaf per tool call or a retrospective completed checklist. Plans are presentation/execution records, not a replacement research workflow.

The following forms apply when the declared tool schema is flat. Call `operation=get` alone first. The result contains the plan, revision, turn_id and allowed `actions` for each ID. No request wrapper, operation=write, or operation=progress. Every mutation supplies plan_id, expected_revision, request_id and turn_id. Reuse the returned identity/revision/turn, with a fresh request_id for changed arguments; an uncertain identical retry keeps its original arguments and request_id.

**Structure:** use create/update/revise/release with a complete flat items snapshot, including unchanged items. Each item has id, content, optional parent_id and kind (group or step). Never send status, title, nested children, or kind=item. Structure edits preserve existing execution states; new items are pending. Create needs a new plan_id and the returned revision (0 only when plan metadata is absent); other operations keep the existing plan_id. Update preserves root IDs, content/order and existing parent links. Revise requires a real scope/structure change and reason; it cannot erase execution history. Release explicitly opts out and preserves the tree, not ordinary completion.

**Execution:** use start/finish/pause/block/fail/partial with step_ids:[id,...], not items or status fields. Choose from the returned actions. Start each executable leaf BEFORE performing its work or opening its checkpoint. Start all affected leaves before a combined command. Finish only AFTER actual completion. Pause while waiting for the user; start again before handling the result. Parallel leaves may run together. Declare containers kind=group before execution if children will be refined later; an already-started leaf cannot become a container or be deleted.

After a rejection, reread the current state and correct the cause. If the work has not happened, start then execute it. If it already happened without a recorded start, report the missing record and block with the observed reason: do not issue a bookkeeping start/finish to fabricate history. A separate verification leaf is appropriate only when actually performing authorized verification. Do not blindly repeat non-idempotent work.

The host records timestamps. Never supply invented durations or infer progress from elapsed time. Pending steps show zero; running leaves accumulate recorded time and completed leaves freeze. Containers sum child times, including parallel work; task total is separate wall-clock time. An empty group cannot complete, and a completed parent has only completed children.

Before a turn ends, reconcile completed work using execution actions, or report partial/blocked/failed stages with their observed reason. Do not declare the final task complete while roots remain pending/in_progress. A genuine mid-work stop names the open stage. On continuation use get and the current turn_id before continued work; the closing action belongs to the turn that obtains completion evidence.

Keep using this tool for the existing tree; do not switch to a native flat plan. If it is absent from the host, discover the current scholarseed_bridge plan/get, plan/structure and plan/action contracts. That lower-level Bridge uses capability/operation/request; do not mix its wrapper with this flat tool. Do not invoke product operations through shell scripts or inspect/inject Bridge credentials.

Existing native threads may retain the older declared get/write tool with a required request field. For that actual declared schema, keep the original wrapper: get has request={}, and write has the complete PlanWrite request with operation and item statuses. Use the returned current state/transitions and request_schema for corrections. Record in_progress before real work and complete afterward; never fabricate missing starts. Do not mix this older presentation with the new flat actions or invent an alias to change it.
