# 项目操作

[English](project.md) · **简体中文**

修改项目文件、运行测试或维护仓库前使用本指南。本指南不授予写入、执行、网络或发布权限。
仅解释代码、不执行也不修改时直接回答。

## 修改前检查

读取适用的项目指令与相关当前源码。涉及 Git 时检查分支、状态和相关差异，保留无关的
已跟踪、已暂存及未跟踪修改。仅在理解受影响行为确有需要时查询历史或 blame。
未经对应授权、未遵守项目规则，不提交、创建分支、推送、revert、reset 或 clean。

定位所属组件并修复根因，不通过压制错误、删除功能或削弱测试掩盖问题。
按项目风格、依赖和架构做聚焦修改。注释与命名遵循项目约定，不施加任意的全局禁令。
未获要求不新增许可或版权头。文本编辑优先使用实际声明的补丁工具及其真实参数。
不为确认成功补丁而重读未变的整份文件；检查相关差异并验证受影响行为。

执行代码或安装依赖前读取[执行环境](execution.zh.md)指南。
项目修改不授权更改用户全局环境、删除数据或进行大范围依赖升级。

## 验证受影响结果

使用项目已有的测试、构建和格式化命令并遵守授权规则。先检查最接近改动的行为，
再按影响扩大范围。项目已有合适测试模式时补定向回归；不顺带引入新测试或格式化框架。
行为变化时更新相关文档。不格式化无关文件，也不为变绿而修复无关基线失败。

区分契约测试、集成检查和真实用户流程验收。报告实际命令、失败和未验证前提；
静态检查不能证明运行行为。验证涉及模型调用、外部服务、安装或破坏性操作时，
先确认对应授权，不把审批模式本身当作这些操作的授权。

## 交付

检查最终差异，概括改动、验证和剩余缺口。源码位置使用真实项目相对路径；
使用可点击会话文件链接时，行号写在标签而不是目标中。不伪造可点击文件，
不把 CLI 行号后缀语法用于产品链接。用户可见文件交付遵守
[文件交付指南](scholarseed-bridge/guides/artifacts.md)；顺带修改的源码不自动成为已发布交付物。
