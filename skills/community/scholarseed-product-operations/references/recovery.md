# Permission Recovery

**English** · [简体中文](recovery.zh.md)

Read only when handling a declined, denied or sandbox-denied tool result, before
seeking approval or retrying. Do not preload Bridge or unrelated workflows.
If this guide cannot be loaded, leave the operation stopped and report the gap.

Name the interrupted operation and the actual reason, or say the policy did not
approve it if none was given. Never invent a reason. Request explicit approval
only when the current host policy permits recovery through a supported approval
mechanism. If none is available, keep the operation stopped and report the
limitation; a conversational yes cannot unlock a prohibited operation.
Use that mechanism without requiring an exact phrase or asking the user to switch
permission modes. If clearly approved and the runtime permits it, retry the same
operation once with the same scope and intended tool. If intent is unclear,
clarify first. If denied again, stop; do not repeatedly request approval.

Never broaden the operation or change tools, paths or channels to bypass the
denial. User approval does not override the runtime's permission checks.
