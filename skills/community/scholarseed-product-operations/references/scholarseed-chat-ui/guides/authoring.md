# Create Conversation Cards with the Official UI

Check the actual catalog in the [Conversation Guide](conversation.md) first to see whether an existing composition meets the goal. Changes to values, copy, chart types, or sources alone do not require a plugin. If the user requests a reusable card or the interaction is not supported by existing compositions, use the host-discovered, available `plugin-create` skill and follow its current `SKILL.md` and relevant references. That skill owns authoring, scaffolding, validation, packaging, and the installation card lifecycle. Do not duplicate its templates or create another generator. If it is missing or disabled, report the gap; do not install it, enable it, or read repository source as a substitute.

## Map the Intent to a Component

Identify the data source, display or input goal, decision the user needs to make, how its result is used, and the cancellation path. Do not ask again for known details or impose a research plan or new workflow just to use a card. For ordinary declarative composition, use the bundled [Conversation signatures](../conversation.md). Only when an executable custom plugin is needed, call `component/catalog(include_ui=true, ui_mode="sandbox")` to discover actual exports and `inputs` and `use` entries in `ui.catalog.composition.Conversation`, plus controls in `families`. Catalog callbacks are controlled host or local bindings, not serializable JSON fields or extra business APIs.

Declare a schema 2 plugin using the verified `plugin-create` authoring contract. Root skill instructions must explain when to call the slot, what real input to send, how to consume action results, and how to handle cancellation and failure. JavaScript, a descriptor, or preview JSON alone does not display a card. A package can contain multiple components. Keep package, skill, and version identities consistent. Use `component/preflight` for new custom slots; do not claim a public slot or another plugin's slot.

Catalog `inputs` list argument names, not complete nested types. If a shape is not declared, check the current authoring contract or the owning domain operation. If still unclear, report the gap. Do not invent literature, citation, or file objects or use synthetic design preview schemas as production inputs.

## Use Only the Official Implementations

Declare actual compatibility and required named exports under the descriptor's `ui` field. The `Conversation` dependency provides the full conversation family; declare top-level exports such as Content separately when the catalog requires it. Dependencies do not grant business permissions. Use `window.scholarseedUI.React`, official controls, and actual components from `window.scholarseedUI.Conversation`. Receive host state through `mount`. Do not copy React, component implementations, or themes, or fetch dependencies such as ECharts or TanStack from remote sources. The official charts and tables already provide those capabilities.

Use the official semantic styles and composition boundaries. Let the host own the background, theme, typography, reading width, and spacing between messages. The composition owns spacing between related blocks; each component owns its content. Do not nest full-page white backgrounds, stack Canvas and card borders, or duplicate padding. Bind charts to the actual container and use the official responsive implementation. Do not pass raw ECharts options, executable formatters, remote resources, or automatic downloads.

`window.plugin.onState` provides host snapshots of `data`, `draft`, `status`, `revision`, `theme`, and `language`. Wait for an actual `save(values)` receipt before treating a JSON draft as saved. Keep edits separate from saved revisions; theme or status updates must not clear unsaved input. Submit answers with declared `submit(action, values)` and wait for the resulting state. Use only declared and available `request` capabilities for business operations; do not mix the two.

Official text, research, chart and table, and Content components used in `mount` register their copyable content together. Icons, menus, and layout containers do not generate prose. Register additional custom text inside components with the declared `useCopyContent(text)`; do not combine it with card-wide `setCopyContent`. Use `setCopyContent` only when rendering the entire card yourself, and check failure and retry behavior. Register saved selections from the new `onState` revision, preserve collapsed content and real sources, and do not treat artifact paths as files already read. Users copy the whole answer below the message. Do not add a card-specific copy button or touch the system clipboard. Follow the `plugin-create` interaction reference for exact behavior rather than guessing permissions or arguments from UI labels.

Use real domain operations for the identities, sources, and states of public literature, citations, artifacts, plans, confirmations, and execution records. Do not fabricate receipts, runtimes, authorization, Lean verification, or exact source locations. If a callback is unavailable, keep the display read-only and explain the gap. Do not add fake open or save buttons or bypass the sandbox to reach the host.

## Separate Checks, Preview, and Actual Use

Provide accurate input, output, and action schemas, preview responses for each action, valid submissions, and invocation payloads. Validate both `data` and the envelope, as well as confirm and cancel, repeated edits, save failures, recovery, long content, themes, and narrow containers. Use the current authoring CLI's validate and pack commands to check the entire archive. Use a new version and archive after changes. Static validation does not execute interactions, and a preview does not prove that the skill's model workflow ran.

Publish the validated ZIP and follow `plugin-create` to call the actual `plugin/install` and produce the host inspection, preview, and installation card. A request to create a card does not authorize installation; the user must confirm in the card. Do not call internal installation APIs, copy into the installation root, change enablement automatically, or treat publication as installation. After installation, use a new real turn to read the current catalog, call the actual slot, operate the card, and inspect the return value. If only creation or preview was completed, say that actual use has not been verified.
