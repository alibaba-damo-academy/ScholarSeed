# Research Results and Citation Components

Place genuine product citation links next to the claims they support. The ScholarSeed host opens citations and displays sources. Do not create citations with declarative components: a source string is not a host verification receipt.

Keep inline citations in ordinary conversation and let ScholarSeed display the sources at the end of the answer. Do not append a duplicate sources list unless the user explicitly asks for a bibliography.

There is no standalone evidence selection card or generic evidence selection slot. Use the host's native interaction when clarification is needed; do not ask for extra confirmation just to display excerpts.

## Literature and Citation Workflows

For search summaries, full result lists, bibliographies, full-text downloads, and delivery, use the actual checkpoints, authorizations, and object identities returned by the existing literature tools. Do not invoke these public slots with hand-written data through `component/request` or `component/display`. This package refers to the official implementations; it does not override their slots.

For [standalone retrieval](../../scholarseed-bridge/guides/retrieval.md), start with the appropriate existing retrieval skill. If the skill or capability is unavailable, report the gap instead of inventing results. Follow the [bundled operation contracts](../../scholarseed-bridge/README.md) for the literature and resource operations you need. Cite actual navigation URLs or citation receipts returned by the tools. Neither a `source` string nor an `excerpt` is a host verification receipt.

Check each claim against the passage actually read, including its conditions, values, and units. State evidence gaps; a citation number alone does not establish support. Selecting evidence does not authorize downloading full text, importing it into a library, reading another conversation, or opening arbitrary external links.

Combine with the chart, rich content, or artifact workbench guides when needed. Reuse existing data and object IDs instead of repeating retrieval, duplicating workflow state, or asking for confirmation again.
