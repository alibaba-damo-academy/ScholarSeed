# 文献综述

[English](README.md) · **简体中文**

综述卡片复用共享文档预览，并通过回执在宿主工作台打开详情。技能开发预览使用
合成样例，不访问真实会话或运行模型，也不代表完整正文验收；详情中的正文操作
仍通过已声明的宿主能力执行。

本 Skill 生成完整综述、Related Work、单章或无标题片段。支持快速与标准模式。
深度模式未实现。执行规范以 [SKILL.md](SKILL.md) 为准，模式取舍见
[执行模式](SKILL.md#3-mode-matrix)。

用户未指定时，两种模式均采用 numeric（数字编号引用）。标准模式默认 PDF，中文使用标准中文模板，
英文使用 NeurIPS；快速模式默认 Markdown，不使用模板。这些设置在执行方案中展示，供用户确认。

## 任务准备

长命令保持在宿主受管的前台会话中；yield 等待间隔不是执行截止时间。继续等待返回的同一会话，不用 `nohup` 或 shell 后台化。多个字段不清楚时，用 `writing configure --describe-input` 一次获取完整输入契约。

大纲图片示例在内容规划和绘图指导中使用叙述引用 token，并以 paper_ids 中的纯 ID 作对照。Quick 与明确禁图的请求不插入图片示例；综述片段中的资产仍放在中间章节。

章节写作明确要求完成全部正文、计划子节与分析任务，仅省略脚本已提供的章节标题。摘要保持独立的正文生成边界。

来源补齐同时覆盖图表叙述字段，更新资产自己的来源清单，保留空清单代表全语料可用的语义。可选限定条件使用数组（无内容时为 `[]`）；不需要的绘图指导可省略或设为 `""`，不使用 null。Quick 将完整引用 token 视为不可拆改的身份，并展示正文中的引用位置。

完整综述的大纲示例将含表格章节放在两个普通章节之间，展示资产之后仍继续展开。该示例仅说明布局，不规定章节数量，也不代表完整综述；单组件示例保持原有范围。

中文摘要默认建议300–600个汉字，英文摘要保持150–250词。长度检查仅为建议，用户或模板的明确要求优先。Quick 引用指导提供了在正文中原样使用完整 token 的示例。

大纲规范化将章节明确引用但漏分配的语料内论文补入来源清单，并记录补齐项。存在显式局部指令的章节需复核，不自动扩充。章节输入展示全文资产分配；仅负责表格的章节接收表格排版与题注指导。Quick 模型输入提供完整引用 token，而非裸引用键。


标准模式提卡使用框架与 AI 解读共享的 `card`、`common_fields`、`source_map` 区块协议，
不额外生成用户读物。框架组装并校验为原有 L1 JSON，写作、引用身份及兼容旧卡片复用保持不变。
区块完整但 JSON 语法错误时，只修复语法，不发送原文或图像；缺区块与内容错误仍走基于原文、
受字段白名单约束的恢复，不放宽证据校验。快速模式继续直接使用摘要，不提卡。


证据诊断保存在综述工作区内部的 `_logs/evidence/<阶段>-<运行ID>/`，不作为文稿交付。
每次执行独立保存带时间戳的事件及完整、已脱敏的响应文件，包含提取失败结果、修复返回字段、
模型用量、来源回退、下载重试/缓存复用，以及分开的下载与解析耗时。解析文本同时记录字符数、
UTF-8 字节数和保守的字节级 token 上界，不冒充精确模型分词数；真实请求 token 用量另记。
文件可能含未公开论文的派生内容，不应作为综述成果发布；诊断记录不证明提取成功。


自动路由与手动选择共用轻量综述准备，不调用 ARG，复用已明确的意图与回答。
先确定有用户依据的主题和材料范围；主题或仅限指定论文的集合缺失时，只追问这些缺失的研究输入。
文献库可访问不等于用户已选定材料。保留明确委托，只解决必要歧义，按需收敛过宽范围，
允许用户明确选择全景覆盖；最多三轮。语言、格式、模式等交付设置留到后续执行方案一起确认，
方案明确展示实际主题和材料范围；完整请求不增加准备追问。准备齐备后按 SKILL.md 中的字段映射构造完整初始化请求；运行
契约保留在主流程中。初始化保存 writing_request.json，
产品准备判断来源就绪情况。后续执行方案通过设置及默认值对实际工作的影响向用户说明，
用户询问技术细节时仍可解释。

## 架构

Quick 使用单次 Markdown 写作，Standard 使用原生分章生成、图表装配、源码精修和出版，
不提供其他写作路径。公共排版前导由布局模块持有。任务配置和确认仅负责管理，不是独立写作引擎。

MA 负责用户意图、前置方案、调度、例外和交付检查。检索 SA 调用独立的
agentic-search。标准模式的绘图 SA 只在计划包含图片时启动。LS负责大纲与写作；
标准模式另做证据提取和精修。代码负责装配、出版、协议及身份校验。

快速模式只读原始摘要，只交付Markdown。它不读取或下载全文，不提取卡片，
不要求句级溯源，不生成图片，不编译其他格式。大纲后用一次写作调用完成所需的
全文、章节或段落。图片、PDF、DOCX等要求须在首轮方案中推荐标准模式，不能默默删去。
标准模式保留全文优先、摘要回退、paper card、分章并发、图形和一次完整输入delta精修，
支持已有PDF、DOCX、Markdown及不同内容粒度。两者共用书目身份、授权及恢复边界。
标准模式装配章节与所需图表后，执行一次完整输入的常规精修；检查范围、语言、格式、
引用与实际交付。精修失败保留v1、原始响应和诊断，不把失败报告为成功。
不增加逐段事实审计或独立科学复核。框架原子能力生成卡片、通用字段和来源映射，
跳过人类阅读正文及展示摘要；综述仅消费纯内容投影和普通论文引用键。

框架缓存以原文版本区分资产，不依赖可见文献记录。有效卡片直接复用；没有或抽取失败时
才生成，成功后保存，失败不替换有效结果。缓存本身不自动入库；用户后续显式导入题录或
PDF时关联匹配原文和既有L1，之后阅读可从同一资产生成，不重新抽卡。
题录补全和来源优先级只作用于任务视图，不回写用户非空或空字段。

新任务在检索前展示方案。产品 HIL 等待用户确认或修改；默认五分钟未回复按
已展示方案执行。用户明确要求等待时禁用超时。明确修改只更新相关字段。
默认不再增加大纲后的确认；用户要求的额外检查点仍须执行。
全文授权独立保留，方案超时不授予论文权限。用户结束后显式加入文献库，不因缓存自动入库。

输入原文统一为PDF。PaperHub使用已验证的pdf=true；解析、片段编号和覆盖状态由
框架PDF工具持有，综述不维护LaTeX输入解析或本地映射校验系统。输出仍可用LaTeX生成PDF。

PDF 在布局解析前先用轻量文本探测正文边界（最多探测200页）。独立参考文献标题需有
文献条目佐证，补充材料封面需有明确标题；目录和普通正文提及不作为边界。确认边界时
保留边界所在整页，允许少量引用随正文进入后续提取，避免丢失同页正文。候选正文不超过
40页时全部解析，超过40页时仅解析前20页和后20页；未确认边界时对整份PDF使用同一解析页数限制，
包括超过200页的文档。原文件不变，原始页码继续用于证据定位。选择页码、边界和探测异常
只写本地解析诊断，不新增主agent确认、裁剪通知或降级提示。

图、表和公式的布局边界告警不拒绝成功提取的文本；仅有这些布局告警且提取到非空文本时返回OK。损坏文件、
不安全压缩包和无可提取文本仍保持失败。LaTeX数学分隔符按转义奇偶顺序扫描，未闭合
公式不触发回溯搜索。

LaTeX 章节使用现有模板的一份简短能力说明，涵盖已加载宏包、数学记号与字体。
指标函数使用明确给出定义的双线大写符号。v1 在现有一次 refine 前进行最多 10 秒的
单次预编译：成功时不增加 refine 上下文，源码错误作为修复输入，超时或工具不可用时
使用同一份模板能力说明和修复要求。预编译输出位于 `_internal/compilation_precheck/`，
不覆盖正文或交付物，也不替代 v2 的最终出版编译。

## 任务和来源

`01_input/writing_request.json` 是任务真源。execution 决定执行策略，deliverable
表达文档类型和粒度，sources 决定允许的语料范围，publication 决定交付格式。
原始意图不可变。追加指令按原文保留，不以阶段建议覆盖用户要求。

任务激活统一准备精确选中的文献：产品补全可信的空缺题录字段和可获取的原始摘要，
保留版本、补全来源和全部原选项。两种模式共用摘要准入；就绪论文进入本轮语料，
缺摘要或身份/书目仍有缺口的记录进入可见待补清单，不阻塞其他就绪论文。
产品在返回激活、方案和大纲确认结果前，将原始对象保存到任务内的内容寻址回执文件。
MA 直接把 `receipt_ref` 交给 `--receipt`；CLI 校验摘要、操作类型和任务绑定，再消费原始对象。
方案的自由文本仍由 MA 解释成行动与变更补丁；大纲批准从同一回执读取用户原话和身份。
`papers import-selected --receipt REF` 消费准备清单，公开 CLI 不再接受逐篇 `items[]` 拼装。
旧任务的材料快照继续读取，回执不替代当前回合激活或全文授权。


仅已确认执行的工作流按产品操作计划指南启用持久阶段跟踪；讨论或草拟方案不启用。
遵循指南中的 Bridge／专用工具路由，复用返回的 revision，只在阶段边界维护。
不保存进度 JSON、不调用 `slr progress`；出版必须在 publication 启动后执行。

构造请求时使用 [SKILL.md](SKILL.md) 中的来源权限映射。请求使用准确参数值，向用户则用自然语言解释
允许使用哪些论文、是否补检。仅在不确定字段时查询输入说明。仅限指定论文时使用已就绪的子集，不补检；
没有可用材料时等待补充。允许补检时按已就绪的唯一论文数计算补检量。Standard 在选中与新增论文合并、去重并冻结后，
通过一次产品全文授权读取原文或复用兼容L1。PDF由框架解析为统一资产；不额外派发模型补读对话。本地PDF快照导入仍属于标准模式。

语料冻结前，重新激活实际任务可纳入用户刚补齐的摘要；冻结后补充只更新文库，
当前任务沿用原快照和成果，新增材料留给后续任务。已有工作区保留其原始导入回执。

`papers budget` 返回实际补检量。搜索SA返回该数量；超量先按返回顺序截断，再去重，不自动补搜。用户材料不按模式默认篇数截断。无可用来源、
摘要、作者或年份缺口按既有来源政策处理，不通过生成假元数据补齐数量。

## 论文身份

写作上下文将任务与设置 JSON 和未转义的论文证据分区呈现。
保留用户要求、研究范围和适用约束，不传执行预估、确认设置或来源定位符。
分章输入只保留一份本章计划和一份完整的本章图表清单，保留科学含义、限定条件、
归属与引用标号。摘要仍并行生成，按论文类型选用贡献、主要发现、适用条件与作者明确的局限，
不再输入完整卡片；选中的字段不截断，稀疏卡片回退原始摘要。其他章节保留已分配卡片的完整业务内容。
Quick 模型输入保留标题、年份、摘要和完整引用 token，不带作者列表或重复的裸引用键；内部书目映射保留原引用键。
图表 brief 只提供一次共用要求和模式契约；单图 packet 仅含局部规划与证据引用，
除非已明确指定，否则不预选图片模式或尺寸。不改写已保存卡片或用户要求。
大纲不再包含章节依赖图；必要定义及其来源放入本章描述、分析任务和论文分配。
章节角色只决定内容职责与证据范围，不控制执行先后。摘要继续使用全局轻量视图并行生成，
绘图基于确认的规划与材料，不等待章节正文。装配仍等待必需图表齐备，已有全稿精修统一完成文本。
出版所需的源码文件与图表依赖保持不变，不静默迁移旧工作区的大纲协议。

原始 paper_id 只用于内部关联。大纲请求使用 P 别名，文字中的论文引用使用显式
`[[paper:P01]]`。适配器按请求映射恢复结构化身份和正文引用键。引用字段与
叙述字段分开解析，不全局替换普通 P 文本。歧义、未知别名或错请求绑定明确失败。

每次请求保存原始响应与映射，规范化候选单独保存。外部响应通过
`outline import` 绑定原请求和证据摘要。章节及前置概念中的引用必须属于实际
下发证据。ID 解析正确不等于科学主张已经通过原文审核。

## 出版

最终文件由单数 `deliverable` 返回，`source` 指向可编辑稿件；workflow 与阶段报告保留各自结构。LaTeX 的 `compile.origin` 记录调用ID、主源码文件SHA-256（不是全部依赖闭包）及 `_logs/compilation/` 下的清单。每次LaTeX/BibTeX命令都有按执行顺序编号的pass记录和保留的输出、引擎日志快照；`diagnostic_pass_index` 标明最终诊断轮次，`log_path` 指向对应快照。引擎日志变化标记只记录文件变化，不保证全部输入溯源完整。溢出数值相同不证明读了旧日志，日志中的字形转储也不是引用校验结果。

PDF 使用现有中文或英文 LaTeX 模板。Markdown 与 DOCX 共用原生 Markdown 源。
DOCX 通过 python-docx 和 markdown-it-py 本地导出，不调用在线转换服务。
支持标题、正文、列表、表格、图片、参考文献和常用可编辑 Word 数学结构。
不支持的公式命令明确失败，不静默删除或转换为错误的数学表达。

脚本交付可编辑 v2 后，MA 直接修改 v2 及实际依赖，再运行 `workflow publish`。
出版不依赖生成阶段 JSON 作为编辑许可证，也不重新装配覆盖修改。
旧工作区不自动迁移，不改变既有用户状态。

PDF 检查首页与图表实际页。DOCX 必须在产品文档查看器中打开检查。
结构校验和可解析文件都不代表真实视觉或科学性验收。

### 本地参考文献题录协议

Markdown 出版保留原有可见参考文献文本与 `ref-<citekey>` 定位，在空锚点的
`data-scholarseed-reference` 属性附加 UTF-8 JSON 的百分号编码。版本为 `1`，
`title`、`authors`、`year`、`publication`、`url`、`doi` 均为字符串，缺失值为空字符串。
数据仅来自当前出版输入的本地 BibTeX 条目；numeric、IEEE、ACM、GB/T 与 author-year
共享同一生产入口，不联网补全，不从排版后的参考文献反推字段。

Desktop 只接受受限长度的已知版本与字段类型，将题录视为不可信文本；属性编码与锚点
ID 转义不授予 HTML 执行能力。标题原址仅允许 HTTP/HTTPS，缺少原址时可用明确 DOI
构造 DOI 链接。未知版本、损坏数据及历史无题录文档仍保留原引用定位，仅展示真实
原始参考文献，不猜作者、年份或期刊。Markdown 编辑须保留完整空锚点属性以支持重开。

## 时间与模型

大纲生成的 temperature 为0.6，并通过请求中的布尔字段 `enable_thinking` 开启思考。其他阶段保持原有设置。


处理时间只是预估，超出预估仍继续完成约定工作，说明已完成内容、当前阶段及有依据的
剩余时间；仅仅变慢不需要再次确认。真正的任务变更或需用户处理的阻塞仍保留确认边界。
内部 execution.budget_seconds 字段表示处理时间预估，不是执行截止点。
`_status/budget.json` 保留脚本与受托检索的区间记录；该局部观察不等于模型有效工作时间
或端到端耗时，完整过程需产品 Trace 补充，不是性能保证。

优先使用公共 skill_model_client。框架拥有模型路由、凭据、审核和传输重试。
仅公共模块导入失败可选原有独立传输；运行上下文或请求失败不能绕路。
不保存凭据，不修改用户模型配置，不为某模式私建 Python 环境。

## 分发和验证

Skill 源码位于本目录。版本、生成的包清单和产品依赖必须一致。逐文件清单随构建生成，不提交到 Git，不手工编辑生成的 pack。
仓库维护者使用 `skills/ADAPTATION.md` 中的冻结与预打包流程。

macOS 使用绑定 slr，Windows 使用绑定 slr.cmd 或产品 Python argv。相对路径均有
明确工作区基准；外部文件和系统接口需要绝对路径时由边界解析。保持原有跨平台

## 出版选项


中文PDF默认使用**标准中文模板**（`standard_chinese`，源文件 `assets/templates/standard_chinese/standard_chinese.tex`），保留旧任务标识 `ctexart` 的读取兼容。
英文PDF提供NeurIPS、IEEE Transactions、ICLR、ICML、AAAI布局；模板来源和冻结摘要见 `assets/templates/manifest.json`，模板与引用样式独立选择。
GB/T 7714—2025条目省略在线载体后缀和引用日期，原始来源元数据仍在内部保留。
Standard默认5个章节并发；显式图表数量受校验，未指定时分析材料后按需决定，允许为0。
Quick支持Markdown表格，不支持图片；需要图片时须实际确认改用Standard。
