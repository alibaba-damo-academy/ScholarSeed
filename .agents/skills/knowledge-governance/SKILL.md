# Knowledge Governance

Use the [knowledge architecture](../../../docs/architecture/knowledge.md) and [documentation index](../../../docs/index.md) to find the canonical document and its consumers.

Check each claim against current code, a verified command, or an authoritative contract. Classify findings as current, duplicated, outdated, or unverified. For authorized updates, edit the owning document, link existing entry points to it, and verify the affected paths and anchors. Do not claim a new capability from a plan. Keep task evidence local.

Use the [repository verification guidance](../../../docs/runbooks/development.md#choose-commands-and-evidence-by-change) for documentation checks and report uncovered areas.
