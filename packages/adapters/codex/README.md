# scholarseed-codex

An independent adapter for the official Codex App Server. It converts unified Runtime commands into native calls and converts native notifications and approval requests into the Runtime protocol.

<a id="边界"></a>
## Boundaries

- Depends only on the public `contract` from `scholarseed-runtime`, in one direction;
- **Does not** depend on the `scholarseed` product backend (`apps/serve`) or Desktop;
- Does not own product authentication, product sessions, or UI logic — those belong to Serve.

### Native planning / 原生计划

Open and resume requests can disable native `update_plan` with `native_plan_enabled=False`.
ScholarSeed Serve uses this setting for its sessions and enables structured tracking
through the product Bridge on explicit user or workflow demand. Other adapter callers
retain the native default. A same-name service tool and generation-only mode also
disable native planning.

创建或恢复会话时可通过 `native_plan_enabled=False` 关闭原生 `update_plan`。
书深 Serve 使用此设置，用户或工作流明确要求时通过产品 Bridge 启用结构化跟踪。
其他适配器调用方沿用原生默认值。同名服务工具及 generation-only 模式也会关闭原生计划。

## What It Provides

`ModelCapabilities.native_agent_messages=False` constrains `multi_agent_version` on the corresponding frozen catalog row to official V1 and disables the V2 override in that model's Thread config.
Other native metadata (including Lite, tool mode, instruction templates, and unknown extension fields) remains unchanged; unknown or supported connections do not change backend selection. V1's `fork_context=true` inherits context through native FullHistory; local spawn, send_input, and wait do not depend on managed AgentMessage. Existing V2 Threads retain their historical version; this projection does not migrate, delete, or textualize their encrypted history. When unsupported, the product capability terminal state still rejects explicitly.

`OpenSessionRequest.fork_source` can create a new Thread from the end of a completed turn in an existing native thread under normal resource admission, mapping to the official `thread/fork` `lastTurnId` (including that turn). The product must verify source-session ownership, the completed turn, and the source binding, then inject the new task's own execution scope, credentials, and instructions; the Adapter does not copy product events, files, approvals, or queues. After a successful native fork, the one-time thread-opening intent is cleared, so later configuration updates and recovery do not fork again. This session-opening path does not declare the existing, unimplemented `RuntimeSession.fork()` available or enable its capability.

Error attribution distinguishes executable-entry probing from physical Host startup. During Host startup, preserve the existing `AppServerError.safe_error`, including MCP publication failures; startup exceptions without an explicit safe error code are classified as `codex_host_start_failed` and must not all be misreported as `codex_executable_unavailable`.
System logs retain the original exception and call chain; public errors pass only the safe error code.

Execution requests can explicitly authorize cross-session reuse for the same principal through `process_sharing_scope`; both platforms use the same rules. The Host compares startup cwd, Skill roots, the frozen process environment, and startup arguments. Ordinary Thread sandbox, approval, network, cwd, or permission profiles no longer define process compatibility.
Product session IDs, Threads, and leases remain independent; models, instructions, dynamic tools, and the complete permission profile are supplied per Thread. Managed sessions start the Host with the existing private discovery home, while Thread cwd remains unchanged; non-sensitive `execution_environment` is projected per Thread, and caches remain in each session directory, without merging directories or permissions.
Different principals, unknown sharing scopes, different credentials, or different startup environments are not merged.

The first valid grant locks the execution Host's process configuration. Later conflicts return
`runtime_host_configuration_conflict`; they are not queued for automatic replacement, do not create a second execution Host, and do not interrupt existing owners. The lock persists across zero Threads, explicit resource draining, failures, and recovery with the same configuration; ordinary configuration admission does not switch it. After the host blocks new tasks as directed by the product, explicit `reconfigure(HostWarmupRequest)` reuses real draining, exit, and resource cleanup, then clears the old configuration lock and grants the target under the same preparation lock, preventing default prewarming from reclaiming the old configuration. Ordinary resource release still does not unlock it, and no second Host is added. Principal and control-write uncertainty fences remain; a login-identity change can take over explicitly only after the old Host has actually drained.
Logout immediately fences the old sharing scope while admitted operations may finish. An unowned Host exits after the native idle check; a busy or unknown-state Host retains its physical resource lease, is not force-killed, and is not reported as released. If starting the target fails, the fence remains in place; do not falsely report recovery of the old configuration. Current deterministic regression coverage does not equal macOS/Windows product acceptance.
Multiple Threads with the same configuration continue to run concurrently; a larger or unlimited physical budget does not remove this admission restriction.

[project.entry-points."scholarseed_runtime.providers"]

<a id="设计决策正文流式与阶段确认解耦"></a>
## Design Decision: Decouple Body Streaming from Phase Confirmation

Confirmed on 2026-10-15: phase metadata may be delayed, but body deltas that have already arrived must not be delayed as a result.
The `phase` of `item/agentMessage/delta` may not yet be known; that does not mean the body cannot be displayed or that it should be classified as reasoning. The Adapter should send body deltas immediately and omit `phase` while it is unknown, without guessing `commentary` or `final_answer`. When the authoritative phase arrives, correct the classification through the existing completion event and message identity; do not append text that has already been output a second time.

This decision chooses “output immediately, confirm the phase later” and rejects “buffer until the phase is known, then output”: although the latter ensures that every delta has a phase, models that provide the phase only at completion would degrade to whole-body output.
It also rejects fabricated phases and frontend typing animations: the former corrupts message semantics, while the latter hides real transport latency.
Messages whose phase is already known continue to carry it on every delta. An out-of-order path where a delta arrives before `item/started` must not replay the body; a completion message that never received a delta must still be displayed through the existing completion path.

Responsibility belongs in `scholarseed_codex/turn.py`; do not add model-specific cases, timing thresholds, or a new Runtime protocol. Historical commit `0952a2966` supported real-time output with an unknown phase, while `a67ed1739` changed the behavior to wait for the phase. This change moves forward to meet the user-confirmed interaction requirement; it does not undo the entire historical commit.

Regression checks must inspect visible events after every delta and before the item/turn completes; checking only that the final text matches is insufficient. Also verify that no label is fabricated while the phase is unknown, late phase confirmation does not duplicate output, and the final phase is correct.
Real Desktop acceptance should observe the body growing multiple times before completion and verify body-delta timing in Trace. An HTTP streaming response, final screenshot, or passing contract test alone does not constitute acceptance of real streaming.

Automated protection has three layers: `tests/contract_codex_adapter.py` checks incremental sends before completion and deduplication after late phase confirmation; `apps/serve/tests/contract_codex_service.py` checks that a body with no phase is published as a product message before completion; `apps/desktop/src/renderer/src/transcript.test.ts` checks that the same message continues growing before phase confirmation and is reclassified in place afterward. These cases are included in the existing Adapter/Serve suites and Desktop test discovery path; they are not isolated scripts invoked only by hand. Real-model behavior and continuous DOM growth still require Desktop acceptance. Neither a final-response assertion nor the layered contracts in this section prove end-to-end streaming acceptance.

## Verification

`tests/contract_codex_adapter.py` checks ABI mapping and capability declarations; `tests/contract_codex_isolation.py` checks discovery isolation using a real App Server and hostile parent directories; Serve contracts check product projection. Contract tests cannot replace acceptance of real Electron conversations, tool calls, and official session recovery.

The Windows sandbox resource port `prepare(local_group, *, cwd)` must carry the cwd for this execution.
ABI 6 is incompatible with older host callbacks; Runtime/Codex 0.2.1 must be delivered together. Path and ACL policy remain owned by the host.

MCP's optional `startup_timeout_ms` is independent of `tool_timeout_ms` and maps to native `startup_timeout_sec`; omit that native field when unset. The fixed 0.159.0 source has a default of 30 seconds.
A credential-bearing stdio launcher emits a startup-failure event with a fixed schema on stderr, distinguishes the bindings and exec stages, and retains numeric errno/winerror and a correlation ID; stdout remains reserved for the MCP protocol.
After validating the complete schema, the host writes it to existing diagnostic logs at WARNING level without exporting free text or secrets.
This does not change version admission for Codex, MXC, sandbox ACLs, or private-state recovery.

The Windows launcher first adds itself to a private, non-breakaway KILL_ON_JOB_CLOSE Job and creates the child process only after success. If the Job cannot be created or joined, fail at the containment stage and do not execute the MCP command.
The Job handle is not inherited by the child; it remains open until this one-shot launcher exits, at which point the kernel closes it and terminates descendants. This does not depend on whether the official Job succeeds. Explicit standard streams preserve argv containing spaces/quotes and wait for the real exit code; macOS continues to use exec. Native focused verification is required for Windows forced-parent termination and descendant cleanup after normal exit; abnormal exit and reopening of the fully installed build still require CI-artifact acceptance.

The fixed build forwards MCP child-process stderr at INFO level. Managed MCP startup appends only `codex_rmcp_client::stdio_server_launcher=info` after the existing `RUST_LOG` (an empty value preserves the error default for other modules), ensuring the fixed schema reaches the host. Other stderr remains limited to summaries/fingerprints; free text is not written to product logs.

Consume native stderr in chunks, buffering at most 64 KiB per line. For an overlong line, output only its length and SHA-256, then continue reading the next line. Do not apply StreamReader's protocol line limit to the diagnostic pipe or export truncated content.

RPC rejection logs also retain the reviewed `native_stage`, `native_code_type`, and `native_code`, associated with request ID, host PID, generation, and error fingerprint. Unknown stages or absent system error codes remain empty; do not infer permission/login errors from free text. Setup-completion notifications also project the reviewed stage, system-code type, and system code. Label the initial fixed probe `bootstrap` and the fixed probe during session attachment `thread`, separately from later built-in tool checks. Recognize only reviewed ACL-helper, private-desktop, and runner errors returned by the official implementation. Do not infer unreported setup/ACL-refresh or handshake internals, and do not collect passwords, the full environment, or vendor error bodies.
